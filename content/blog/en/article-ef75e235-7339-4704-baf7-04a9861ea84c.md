## The n8n 2.43 announcement and its date

The n8n 2.43 announcement describes changes to Browser Use in the n8n Assistant, migration reports and Azure OpenAI Chat Model deployment selection. The official release notes give October 6, 2026 as the release date. The release notes do not establish a separate announcement publication date.

This article covers those selected operational changes, rather than the complete release.

Sources: [Release notes](<https://docs.n8n.io/changelog/release-notes.md>)

## Browser Use: availability, defaults and devices

![A desktop monitor and toggle stand across a gap from a phone and tablet in the Browser Use device comparison.](/blog/en/article-ef75e235-7339-4704-baf7-04a9861ea84c/35607339311428a2a171d5e13c168dd8f9ead7b5bc61f5b6f58c0e1134ce6a37.webp)

Desktop and mobile devices are separated to illustrate the device distinction discussed in this section.

For n8n 2.43, the announcement describes [Browser Use in the n8n Assistant](<https://n8n-challenges.app/en/blog/n8n-2-43-release-notes-browser-use-now-on-for-everyone>) as released to all users. The instance-admin setting N8N_INSTANCE_AI_BROWSER_USE_ENABLED controls it and defaults to on. Phones and tablets are excluded, including iPads using desktop mode.

The announcement does not specify edition or hosted-plan entitlements or give a deployment-specific rollout timetable. Its general release-note caveat also says publication does not guarantee immediate availability on every instance.

Sources: [Release notes](<https://docs.n8n.io/changelog/release-notes.md>)

## Migration reports: impact and compatibility

![Four sorting trays hold mechanical pieces beside an inspection rail in the n8n migration-report scene.](/blog/en/article-ef75e235-7339-4704-baf7-04a9861ea84c/5a389bb0d3d913cc0c2bb1b6a0aae7c5c014b733fb12e0690252e3fdb7eb7e7f.webp)

Sorting trays and an inspection rail illustrate reviewing runtime impact and compatibility as separate signals.

The n8n 2.43 changes replace migration-report severity labels with categories describing runtime impact. A progress bar also shows workflow compatibility with the target version. These are announced reporting changes, not evidence of successful upgrades or measured reliability improvements. The categories are:

- Upgrade blocked
- Executions fail
- Behavior changes
- Capability removed

We think runtime impact is a more useful starting point for an upgrade discussion than an abstract severity label, because it directs attention to what the team needs to investigate.

Sources: [Release notes](<https://docs.n8n.io/changelog/release-notes.md>)

## Azure deployment selection depends on node version

![Two connector assemblies have different controls in the Azure OpenAI Chat Model node-version comparison.](/blog/en/article-ef75e235-7339-4704-baf7-04a9861ea84c/73d8f3cbd500753183e472c441c8114fffdcfdfa27884d9fc2df29d4d435adf1.webp)

Different connector assemblies illustrate the distinction between new and existing Azure node versions.

For Azure OpenAI Chat Model users, the n8n 2.43 update adds deployment selection to new node version 1.1. Listing deployments requires an Azure AI Foundry credential with a Project set. Existing version 1 nodes retain their text fields and saved values.

The announcement describes errors for classic credentials or empty projects, but does not supply a complete credential-configuration or troubleshooting procedure. The deployment selector should therefore be understood within those stated prerequisites.

Sources: [Release notes](<https://docs.n8n.io/changelog/release-notes.md>)

## What teams can review now

![Hands examine a toggle, sorting tray and connector, with an ownership token beside one object, for an n8n update review.](/blog/en/article-ef75e235-7339-4704-baf7-04a9861ea84c/f77146e30d4e448052e6818b86a9162d88a11c6eb382d2b26567c5f00560d4ea.webp)

A shared workbench illustrates the suggested team review and assignment of responsibilities.

The n8n 2.43 announcement does not provide a complete [upgrade procedure](<https://n8n-challenges.app/en/blog/n8n-current-version-when-and-how-should-a-self-hosted-team-upgrade>). The checklist below is our editorial suggestion for reviewing the selected changes, not a recommendation attributed to n8n or a validated upgrade checklist.

- [ ] Ask the instance administrator whether Browser Use should remain enabled, and tell affected colleagues about the device restriction.
- [ ] Review migration-report impact categories and compatibility progress.
- [ ] For Azure deployment selection, distinguish new version 1.1 nodes from existing version 1 nodes and check the credential's Project setting.

Our practical view is to give each relevant change a clear owner before deciding what to adopt. A short review of the team's actual setup is more useful than treating the release as one undifferentiated upgrade task.

Sources: [Release notes](<https://docs.n8n.io/changelog/release-notes.md>)
