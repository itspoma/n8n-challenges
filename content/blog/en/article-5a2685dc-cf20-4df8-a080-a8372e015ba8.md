## Prerequisites and the Goal

n8n human-in-the-loop review lets you pause a risky step inside an AI Agent workflow so a person can approve or deny it before it runs, according to n8n's official documentation. Before you set this up, you need an AI Agent node with at least one tool already connected: independent build notes from a practitioner blog note that n8n's AI Agent node currently requires at least one connected tool sub-node, so start there if your agent doesn't have one yet.

You'll also need an approval channel ready to configure, such as a chat or messaging app the review step can send requests through and receive a decision from. The goal for this tutorial is narrow: pick one tool call in your workflow that's risky enough to warrant a second pair of eyes — sending a message, deleting a record, placing an order — and require a human decision before that specific call executes.

- [ ] An AI Agent node with at least one tool already connected
- [ ] Credentials for the approval channel you plan to use, such as a chat or messaging app
- [ ] One tool call you consider risky enough to require sign-off before it runs

## Setting Up the Human Review Step in the Tools Panel

![Three workbench stations show connecting tools to a human review switch in n8n's Tools Panel.](/blog/en/article-5a2685dc-cf20-4df8-a080-a8372e015ba8/3868a452cae63eb32dc5f8a0a112ddac8bab747265db3ea14e9ffb41b62c717f.png)

An illustrative process view of wiring tools to a human review step.

Setting this up happens entirely inside the AI Agent node's Tools Panel, in three steps drawn from n8n's official documentation.

**Adding a human review step to an AI Agent**

1. **Open the Tools Panel**: Click the Tools connector on the AI Agent node to open the panel where tools and the review step are configured.
2. **Add a human review step**: In the Tools Panel's Human review section, choose an approval channel and configure its credentials and settings.
3. **Connect the tools that need approval**: Attach the tools that should require sign-off to the human review step's tool connector, configuring each one as you normally would.

Once connected, only the tools attached to the human review step require approval — other tools on the AI Agent node keep running automatically, so you can be selective about which actions need a second look. n8n's documentation doesn't detail credential setup for each individual approval channel, so follow n8n's own setup for whichever channel you pick, such as Slack, Telegram or Gmail.

Sources: [Human-in-the-loop for tools | Build | n8n Docs](<https://docs.n8n.io/build/integrate-ai/ai-examples/human-in-the-loop-for-tools>)

## What Happens When a Reviewer Approves or Denies

With the n8n human-in-the-loop approval step wired in, running the workflow now pauses at that point: n8n's documentation describes the workflow pausing and waiting for a person to act before the tool call goes any further.

**Reviewer decision and its effect on the tool call**

| Reviewer action | What happens | Tool call outcome |
| --- | --- | --- |
| Approve | The workflow continues | The tool runs using the parameters the AI chose |
| Deny | The workflow continues | The action is canceled and does not run, per n8n's documentation |

What differs between the two outcomes is whether the tool actually executes: approval lets it run with the parameters the AI selected, while denial cancels the action, per n8n's documentation. How the agent is told about a denial determines whether it recovers gracefully or gets confused, which is why the system prompt matters — covered in the next section.

## Writing a Reviewer-Friendly Approval Message and Updating the System Prompt

![Two reviewer message cards, one stamped approved and one denied, sit beside a tool parameter tag.](/blog/en/article-5a2685dc-cf20-4df8-a080-a8372e015ba8/df9ca9b41e179179bc84565118ab2e3873106539cf98bf97499c5ffd9e465a1e.png)

An illustrative comparison of an approved versus a denied tool call message.

A reviewer who only sees a bare 'approve or deny' button in an n8n human-in-the-loop step has to guess what they're approving. A practical pattern worth trying — treat it as a suggestion to adapt rather than a required setting — is building the approval message around the tool's name and the parameters the AI selected, so the reviewer can see exactly what will run before deciding.

n8n's documentation also recommends describing the tool setup and the human review step inside the AI Agent's system prompt itself. Without that context, a denial can confuse the model into repeating the same request or producing an unclear response, so spelling out that certain tools need approval — and what to do if one is denied — helps the agent recover cleanly.

- [ ] Test the approve path on sample data before connecting a real trigger
- [ ] Test the deny path too, since it depends on your system prompt handling rejection well
- [ ] Keep review enabled broadly at first, then narrow it to higher-risk tools once you trust the agent's behavior — a suggested starting point, not a fixed rule
- [ ] Mention in the system prompt which tools require approval and how to respond if one is denied
