## HR Workflow Examples: What You'll Build in This n8n Tutorial

![A paper form, laptop and filing tray represent one of many HR workflow examples in n8n.](/blog/en/article-b1c6b614-0742-42b2-8f0f-dbd0d408e6c9/cc345b0e7ed9ba24d9719bc7ac776d072177087dc296af88331cb3886dedd76b.png)

An illustrative sequence showing how a submission moves from form to stored record.

This tutorial builds one of the more practical HR workflow examples you can put together in n8n: a workflow that takes a candidate or employee form submission, stores it as a permanent record, and notifies the right person automatically. It works whether you're collecting job applications, internal leave requests, or onboarding paperwork, and the same intake-store-notify pattern shows up across many n8n workflow automation use cases well beyond HR, including intake-heavy legal workflow examples like contract requests or NDA approvals.

Vendor write-ups describing n8n for HR automation frame this same shape — creating a record, triggering follow-up tasks, and notifying relevant teams — as the core pattern of an onboarding-style workflow. Treat that framing as one illustrative pattern from a vendor blog rather than a documented n8n feature; the steps below build the pattern from n8n's own node documentation instead.

## Prerequisites: n8n Instance, Google Sheets and Email/Slack Credentials

Before you start, make sure you have a few pieces ready. You'll need somewhere to edit workflows, a spreadsheet to write to, and a way to reach whoever needs to see each submission.

Because this workflow stores candidate or employee names, emails and other submission details in a shared spreadsheet and routes them by email or Slack, check your own team's [data-protection and compliance requirements](<https://n8n-challenges.app/en/blog/n8n-security-checklist-for-a-shared-self-hosted-instance>) for handling that kind of HR data before you publish it.

- [ ] An n8n instance you can create and edit workflows in, whether n8n Cloud or self-hosted
- [ ] A Google Sheet with a header row matching the fields your form will collect
- [ ] Google Sheets credentials configured in n8n, since the Google Sheets node needs authentication before it can read or write rows
- [ ] SMTP credentials for the Send Email node, a Slack workspace connection, or both, depending on how you plan to notify people

Sources: [Google Sheets | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.googlesheets>), [Send Email | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.sendemail>), [Slack | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.slack>)

## Step 1: Create the Intake Form with the n8n Form Trigger

Add a Form Trigger node as the first node in a new workflow. The Form Trigger starts a workflow when someone submits a form, and n8n generates the form page itself, so you don't need a separate form-building tool. Define the fields you need — for example a name, an email address, the position or request type, and free-text notes — and give the form a clear title, since applicants or employees will see exactly what you configure.

**Building the HR intake workflow step by step**

1. **Capture**: A Form Trigger node collects the candidate or employee submission and starts the workflow.
2. **Test**: Submissions are checked against the Test URL inside the editor before anything goes live.
3. **Store**: A Google Sheets node appends the submission as a new row in a prepared sheet.
4. **Notify**: A Send Email or Slack node alerts the person or channel responsible for reviewing it.
5. **Route (optional)**: A Switch node sends different request types to different reviewers instead of one shared inbox.
6. **Publish**: The workflow is saved and published, then the form is shared using its Production URL.

Sources: [n8n Form | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.formtrigger>)

## Step 2: Test the Form Using the Test URL Before Going Live

Open the Form Trigger node and copy its Test URL. Submit a few test entries through that URL while the workflow is open in the editor, so you can watch each submission's data land in the node's output and confirm your field names and values look the way you expect before anything touches your live spreadsheet or notification channel.

Sources: [n8n Form | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.formtrigger>)

## Step 3: Store Each Submission as a Row in Google Sheets

Add a Google Sheets node after the Form Trigger and connect it to the sheet you prepared. The Google Sheets node is n8n's built-in way to automate spreadsheet work, and the operation you want here is Append Row, which adds each new submission as a new row at the end of the sheet. If your form field names already match your sheet's column headers, n8n can map them automatically; otherwise, insert an Edit Fields (Set) node beforehand to align the names.

Sources: [Google Sheets | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.googlesheets>), [Sheet Within Document operations | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.googlesheets/sheet-operations>)

## Step 4: Notify the Right People by Email and/or Slack

![An envelope and a chat bubble both point to a bell, comparing email and Slack notifications in n8n.](/blog/en/article-b1c6b614-0742-42b2-8f0f-dbd0d408e6c9/e4bbae5aec105d7b60800c786df0f9bb386de5ecb3b8e82b1ce701b328bb3fc7.png)

A conceptual comparison of the two notification channels this workflow can use.

With the record safely stored, add a notification step. n8n's Send Email node delivers messages over a standard SMTP server, which is enough to alert an HR inbox or a hiring manager whenever a new submission arrives. If your team lives in Slack instead, the Slack node's Send a Message operation posts straight to a channel, so a recruiting or people-ops channel sees the new submission right away.

One limitation is worth knowing before you rely on this for real communication: the Send Email node can't set threading headers like In-Reply-To, so every automated HR notification email arrives as its own separate conversation rather than a reply inside an existing thread. If threaded replies matter to your team, look at the Gmail node's reply operation instead of the core Send Email node.

That [silent-failure risk](<https://n8n-challenges.app/en/blog/n8n-training-for-teams-one-shared-error-handling-standard>) applies directly to the notification step above: if the email or Slack node fails and nothing else is watching, the record still lands in your sheet but nobody hears about it. As one automation practitioner writing about n8n onboarding workflows describes the stakes of a missed alert:

> “A workflow that fails silently is worse than no automation at all, because you assume onboarding happened when it did not.”
>

## Step 5 (Optional): Route Notifications by Department or Request Type

If different request types need different reviewers — a candidate application versus an internal leave request, say — add a Switch node right after the Form Trigger, or after the Sheets node if you want every submission logged regardless of type, and branch by a field like request type or department. Route each branch to its own Send Email or Slack message so the person who actually needs to act gets pinged, instead of everyone getting a copy of everything.

Sources: [Slack | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.slack>)

## Publish the Workflow: Switching to the Production URL

Before an HR form can be used for real, the workflow needs to be saved and published, not just left running in test mode; n8n's own documentation is explicit that saved-and-published status is a prerequisite for [production use](<https://n8n-challenges.app/en/blog/self-hosted-n8n-production-readiness-checklist>). Once that's done, switch the form's URL from the Test URL to its Production URL and share that link with candidates or employees. Production submissions won't show up live in the editor the way test ones do, so you'll rely on your Google Sheet and notifications to confirm things are working.

Sources: [n8n Form | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.formtrigger>)

## Expected Results After a Submission

After a real submission, a new row should appear in your Google Sheet, and a notification should land in the configured inbox or Slack channel. If you added routing in Step 5, the notification should reach the branch-specific recipient rather than a single shared address, and the record in your sheet should look identical regardless of which branch handled it.

Sources: [Sheet Within Document operations | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.googlesheets/sheet-operations>), [Slack | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.slack>)

## Troubleshooting Common Issues

Most early problems with HR workflow examples like this one trace back to a handful of causes.

- [ ] No row appears in Sheets: check that your Google Sheets credentials are still valid and that field names match the sheet's headers
- [ ] Test submissions work but production doesn't: confirm the workflow is actually saved and published, and that you're testing the Production URL, not the Test URL
- [ ] The record saves but no notification arrives: check whether Continue on Fail is turned on for the email or Slack node; many n8n nodes include this setting, and turning it off means a failed step stops the run and surfaces an error instead of continuing silently
- [ ] Email replies don't thread together: this is expected with the core Send Email node, since it doesn't support threading headers; consider the Gmail node instead
