## Self-hosting and deployment model

![A private server rack beside a cloud platform linked by a bridge, showing n8n's self-hosting versus Zapier's cloud-hosted model.](/blog/en/article-a811fe12-9563-4a5c-9aa7-12f1fb965d7c/c1f02b4c59735623a1ca166429cc794f1f2c0c457a4fd769c2aa97ef76d65dd6.png)

n8n can run on a team's own servers, while Zapier stays cloud-hosted and bridges out to on-premises systems only on its top plan.

n8n's documentation states that it can be self-hosted on a team's own infrastructure, on-premises, or in a private cloud. Without a license key, that self-hosted install runs as the free Community edition, and a Business or Enterprise license key unlocks those paid editions on the same install, according to n8n's own documentation.

Zapier works differently. Its own blog states that connecting Zapier to a customer's on-premises services requires the Enterprise plan and hosting that infrastructure on Amazon Web Services via VPC peering. That describes Zapier reaching into a customer's on-premises systems, not Zapier itself running on a team's servers — the platform stays cloud-hosted either way.

- n8n: self-hostable on a team's own infrastructure, on-premises or in a private cloud, even on the free Community edition
- n8n: a Business or Enterprise license key unlocks paid editions on the same self-hosted install
- Zapier: the platform itself remains cloud-hosted on Zapier's infrastructure
- Zapier: reaching a customer's on-premises systems is an Enterprise-only add-on via AWS VPC peering

We'd be cautious about treating self-hosting as a free option: even on the Community edition, a team is taking on the work of running, patching and scaling that server itself, overhead that Zapier's cloud-only model avoids entirely.

n8n's self-hosting option works the way it does because of how the project licenses its code: n8n's CEO, Jan Oberhauser, has explained in an interview on Sequoia Capital's Training Data podcast that the license lets anyone run n8n for free, including in production, but [blocks reselling a hosted version of it](<https://n8n-challenges.app/en/blog/n8n-alternatives-self-hosted-activepieces-vs-huginn>).

> “What is, however, different in our license is that people cannot commercialize our code.”
>
> — Jan Oberhauser, CEO, n8n · Source: [n8n on Building the Universal AI Automation Layer | Sequoia Capital](<https://sequoiacap.com/podcast/training-data-jan-oberhauser>)

Sources: [Host n8n | Deploy | n8n Docs](<https://docs.n8n.io/deploy/host-n8n>), [Can Zapier connect to on-premises services?](<https://zapier.com/blog/can-zapier-connect-to-on-premises/>)

## Governance controls: SSO, LDAP, RBAC and audit logging

Both platforms gate identity and access controls behind their higher tiers. n8n's documentation restricts [SAML single sign-on](<https://n8n-challenges.app/en/blog/n8n-sso-do-you-need-it-or-are-shared-logins-fine>) to the Business and Enterprise plans, and states that LDAP login is available on n8n Cloud Enterprise and on self-hosted Business and Enterprise editions. Configuring SSO through environment variables rather than the UI requires n8n version 2.18.0 or later, per n8n's documentation.

n8n also separates two levels of roles: built-in project roles are available on all n8n Cloud plans and on self-hosted Registered Community, Business and Enterprise editions, while custom instance and project roles are reserved for n8n Cloud Enterprise and self-hosted Enterprise, according to n8n's documentation.

Zapier's own feature comparison table lists SAML single sign-on as included on the Team and Enterprise plans only, restricts user provisioning via SCIM to the Enterprise plan, and sets audit log retention at six months on Team and one year on Enterprise, per Zapier's pricing page.

- SSO (SAML): n8n Business/Enterprise; Zapier Team/Enterprise
- LDAP: n8n Cloud Enterprise and self-hosted Business/Enterprise
- SCIM user provisioning: Zapier Enterprise only
- Custom roles: n8n Cloud Enterprise and self-hosted Enterprise
- Audit log retention: Zapier six months on Team, one year on Enterprise

Sources: [Use SAML | Administer | n8n Docs](<https://docs.n8n.io/administer/manage-users-and-access/verify-user-identity/use-saml>), [Connect LDAP | Administer | n8n Docs](<https://docs.n8n.io/administer/manage-users-and-access/verify-user-identity/connect-ldap>), [Configure SSO | Deploy | n8n Docs](<https://docs.n8n.io/deploy/host-n8n/configure-n8n/security/configure-sso>), [Set permissions and roles (RBAC) | Administer | n8n Docs](<https://docs.n8n.io/administer/manage-users-and-access/set-permissions-and-roles-rbac>), [Zapier Pricing](<https://zapier.com/pricing>)

## Connector depth: named integrations vs. generic connectivity

![A shelf of many small connector boxes beside a single universal adapter, representing named integrations versus generic API connectivity.](/blog/en/article-a811fe12-9563-4a5c-9aa7-12f1fb965d7c/2427be68cefddc3d6cf518bdd0990a130528945460966d23a2ff4d96a7f0d2d8.png)

A long list of named connectors is one way to reach other tools; a flexible generic connector is another.

n8n's own documentation describes its built-in integration library only qualitatively, stating that n8n supplies hundreds of nodes, without giving an exact connector count. Zapier's own app directory states it connects more than 10,237 apps, though a separate Zapier pricing page uses a lower figure of 9,000 or more apps, so which number is current is not clear from the pages themselves.

We think a large named-connector count matters less once a team is comfortable using n8n's generic HTTP Request node or a custom API call, so what looks like a connectivity gap often isn't one in practice.

## Pricing structure: execution-based vs. task-based billing

n8n's [Starter cloud plan](<https://n8n-challenges.app/en/blog/n8n-pricing-plans-for-teams-cloud-vs-self-hosted>) costs 20€ per month, billed annually, for 2,500 workflow executions with unlimited steps, per n8n's pricing page (state as of October 2026). Its Business plan, required for the SSO and LDAP governance features described above and only available self-hosted, costs 667€ per month billed annually for 40,000 workflow executions, per the same page.

Zapier bills differently. Its Free plan includes 100 tasks per month with unlimited two-step Zaps, per Zapier's pricing page. That is a different billing unit from n8n's per-execution count, though the pages reviewed here do not detail how task consumption works for multi-step Zaps beyond the Free plan's two-step limit. Zapier's Enterprise plan, the tier carrying SSO, SCIM and the longer audit log retention, is not available for self-serve online purchase and requires contacting Zapier Sales for custom pricing, per Zapier's pricing page.

- n8n charges per workflow execution, regardless of how many steps that workflow contains
- Zapier charges per task, with its Free plan allowing only two-step Zaps within a 100-task monthly allowance

Sources: [n8n Plans and Pricing - n8n.io](<https://n8n.io/pricing/>), [Zapier Pricing](<https://zapier.com/pricing>)

## Editorial recommendations for an evaluating team

Before anything else, estimate monthly volume in each platform's own billing unit, since n8n bills per workflow execution regardless of step count while Zapier bills per task, meaning the same workload can price very differently on each. Budget for the higher tier, not the entry plan, if SSO, LDAP, SCIM or longer audit retention are compliance requirements rather than nice-to-haves, since both vendors gate those behind Business/Enterprise or Team/Enterprise.

- [ ] Estimate monthly executions (n8n) or tasks (Zapier) before comparing sticker prices
- [ ] Check which tier actually includes SSO, LDAP/SCIM and the audit log retention your compliance needs
- [ ] Decide whether on-premises data residency requires true self-hosting or just on-prem connectivity
- [ ] Test whether generic HTTP/API calls cover any named connector either platform appears to be missing
- [ ] Re-verify current pricing and plan limits directly on each vendor's site before deciding

Teams still weighing n8n vs Zapier vs Workato as a full three-way decision should go verify Workato's own documentation and pricing directly, since none of it could be confirmed here. Treat everything above as a checklist to re-verify on each vendor's own site rather than a final answer, since both pricing pages are undated and both vendors can change plan limits at any time.

Choosing between execution-based and task-based billing, or deciding which governance tier a team actually needs, is easier with a clear picture of the team's current n8n instance first.
