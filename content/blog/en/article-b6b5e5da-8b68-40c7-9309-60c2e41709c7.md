## What the n8n OData filter injection advisory announced

The n8n OData filter injection advisory published on October 14, 2026 announces that fixes are available and recommends that affected users upgrade. Advisory GHSA-mgpr-56r4-5c67 concerns unescaped OData filter values in Microsoft Outlook contact lookup and Microsoft SharePoint v1 item update.

The n8n Outlook SharePoint security update matters when workflows bind untrusted input into the affected fields. The publication date identifies the announcement; it does not establish when exploitation began or when patches first became available.

Sources: [OData $filter Injection in Microsoft Outlook and SharePoint v1 Nodes · Advisory · n8n-io/n8n · GitHub](<https://github.com/n8n-io/n8n/security/advisories/GHSA-mgpr-56r4-5c67>)

## Which operations and inputs need attention

![A funnel above an open address book sits beside a chute pointing between list drawers.](/blog/en/article-b6b5e5da-8b68-40c7-9309-60c2e41709c7/69d354a00c9dfa863e176304057c35d1bcfc97d0699583aca782e3dd12b468b7.webp)

An address book and list drawers show the two kinds of workflow operations discussed in this section.

The advisory describes two possible consequences of OData query injection: Outlook can return the bound mailbox’s entire contact list, and SharePoint can write submitted values to an unintended list item. Both remain within the stored credential’s scope. These are announced vulnerability consequences, not evidence of exploitation.

For teams reviewing the n8n Microsoft Outlook vulnerability and the affected Microsoft SharePoint v1 workflows, the following inventory is our suggested way to prioritize review; it does not establish that a workflow is safe.

- [ ] Identify workflows using Microsoft Outlook contact getAll.
- [ ] Identify workflows using Microsoft SharePoint v1 item update/upsert.
- [ ] Inspect whether untrusted input reaches the affected lookup fields.
- [ ] Assign an owner to each workflow requiring remediation.

Sources: [OData $filter Injection in Microsoft Outlook and SharePoint v1 Nodes · Advisory · n8n-io/n8n · GitHub](<https://github.com/n8n-io/n8n/security/advisories/GHSA-mgpr-56r4-5c67>)

## Upgrade to a listed patched version

![Hands replace a cracked filter insert in a conduit.](/blog/en/article-b6b5e5da-8b68-40c7-9309-60c2e41709c7/ebb50ea9ee21bc362009e8325f75c27da89c514f857281513ba4aebc347a0c35.webp)

Hands replace a damaged filter insert, illustrating the section’s focus on upgrading.

For n8n OData filter injection, the advisory lists fixes in versions 1.123.85, 2.44.1 and 2.43.5 and recommends upgrading to one of those versions or later. It does not name release channels for those version lines or provide deployment-specific upgrade commands or verification procedures.

We think the practical priority is to give the upgrade a clear owner and make workflow review part of the same response. We would use the inventory to organize that work rather than treat input inspection as a substitute for patching.

## If an immediate upgrade must wait

![A closed gate pauses a workflow conduit while a replacement component waits nearby.](/blog/en/article-b6b5e5da-8b68-40c7-9309-60c2e41709c7/9bfd7cda4870a459b1932fa34f43c3b32435a77dee88057c5a4a3287591c28e3.webp)

A closed gate pauses the pictured workflow while a replacement component waits beside it.

The advisory includes deactivating affected workflows until the instance is patched among its temporary mitigations. It explicitly warns that workarounds do not fully remediate the risk and does not specify operational recovery steps or a complete alternative remediation.

In our view, a temporary mitigation should have a named owner and an explicit [plan to reach a patched version](<https://n8n-challenges.app/en/blog/n8n-current-version-when-and-how-should-a-self-hosted-team-upgrade>). Calling it temporary should describe a decision the team will revisit, not an indefinite operating arrangement.

Sources: [OData $filter Injection in Microsoft Outlook and SharePoint v1 Nodes · Advisory · n8n-io/n8n · GitHub](<https://github.com/n8n-io/n8n/security/advisories/GHSA-mgpr-56r4-5c67>)

## What the announcement leaves unspecified

The n8n OData filter injection advisory does not state whether n8n Cloud instances are automatically patched, distinguish editions or hosted plans, or describe wider impact. It also does not quantify affected installations or exploitation prevalence. Teams should not infer those details from this announcement.

Our editorial suggestion is to record unresolved deployment questions alongside the remediation owner. This article explains the announcement and its immediate response choices; it is not a deployment-specific upgrade or troubleshooting procedure.
