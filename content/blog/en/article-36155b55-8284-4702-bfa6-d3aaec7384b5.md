## Prepare your n8n Google Sheets integration

This n8n Google Sheets tutorial proposes a controlled practice workflow: accept one update request, count exact ID matches, update automation_status only for a unique match, and append exceptions to a separate review sheet. The steps and code are a tutorial design, with acceptance criteria below; no firsthand execution results are supplied.

Start with an n8n workspace, an existing working Google Sheets credential and a copied practice spreadsheet. Credential creation, production scheduling, batch processing, scaling and quota optimization are outside scope. Prepare the following fixtures before building. The example Records table supplies suggested practice data: keep the IDs as text. Submit four requests separately, one per execution, using record_id values A-001, A-002, A-999 and an empty string, each with automation_status set to ready. Leave A-999 absent from Records.

**Suggested practice-sheet design**

| Location | Fields | Purpose |
| --- | --- | --- |
| Records sheet | record_id, automation_status, team_notes | Operational practice data |
| Review sheet | requested_id, proposed_value, classification, match_count | Exception review |
| Request | record_id, automation_status | One proposed update |

**Example Records table: suggested practice data**

| record_id | automation_status | team_notes |
| --- | --- | --- |
| A-001 | pending | Confirm delivery address |
| A-002 | pending | Waiting for finance |
| A-002 | on_hold | Call before dispatch |

We think column ownership is worth deciding before connecting a write node: it makes the intended change easier for a teammate to review.

## 1. Prepare one request and read the rows

![A request slip, ledger and empty envelope represent the n8n Google Sheets read step and its empty-result path.](/blog/en/article-36155b55-8284-4702-bfa6-d3aaec7384b5/1837ee60232818239b5807b6ce2dc5260c8ce5dde901af0db3deff0e68fe0fe7.webp)

One request and a small practice sheet keep the read stage manageable.

Use stable text identifiers in record_id. This exercise uses exact text equality: no trimming, case conversion or numeric conversion. For example, A-001 differs from a-001. Reading every row keeps this small practice exercise straightforward. Build the first nodes as follows.

1. Add Manual Trigger, then Edit Fields named Request.
2. In Request, set record_id to A-001 and automation_status to ready. Keep one request per execution.
3. Add the Google Sheets node with Get Row(s). Select the existing credential, document and Records sheet; leave read filters unset.
4. In the read node's Settings, enable Always Output Data.

n8n documents existing credential selection and default all-row retrieval for Get Row(s). Always Output Data emits an empty item when a node returns no data; the matching code must exclude that placeholder.

## 2. Count matches and route the request

![Matching gates divide the request into a unique-update path and an exception-review path.](/blog/en/article-36155b55-8284-4702-bfa6-d3aaec7384b5/b64ee4d2d9bcbc78558a5f4d1831c510ee21f9098a1826cb8321d1de73714e34.webp)

The suggested routing separates unique matches from requests needing review.

Add a [Code node](<https://n8n-challenges.app/en/blog/n8n-code-node-javascript-debugging-tutorial>) after the read and select JavaScript, Run Once for All Items. n8n supports accessing all input items and referencing a named node's first item. Enter this proposed tutorial code:

const request = $('Request').first().json;
const id = request.record_id;
const valid = typeof id === 'string' && id.trim().length > 0;
const rows = $input.all().map(item => item.json).filter(row => Object.prototype.hasOwnProperty.call(row, 'record_id'));
const count = valid ? rows.filter(row => typeof row.record_id === 'string' && row.record_id === id).length : 0;
return [{ json: { requested_id: id ?? '', proposed_value: request.automation_status, classification: !valid ? 'invalid' : count === 1 ? 'unique' : count === 0 ? 'missing' : 'duplicate', match_count: count } }];

Add a [Switch node](<https://n8n-challenges.app/en/blog/n8n-switch-node-documentation-routing-items-correctly>) with rules for classification equal to unique, missing, duplicate and invalid. Enable its Extra Output fallback. These classifications are editorial conventions. Connect unique toward the update branch; connect the other outputs and fallback toward review.

![Suggested update and review flow: 1. Read; 2. Classify; 3. Route; 4. Verify](/blog/en/article-36155b55-8284-4702-bfa6-d3aaec7384b5/ed36b9a2645277d1cfe46532c9eb504353f72f7be3f8a8cd52252c4c095ff141.webp)

In our view, an unexpected classification belongs in review rather than on a write path. That makes the fallback a deliberate decision.

## 3. Restrict the write and append exceptions

![A broad roller and a fine pen contrast unrestricted writing with designated-column updates.](/blog/en/article-36155b55-8284-4702-bfa6-d3aaec7384b5/b57d0bd3a0274e800a0020911855191a3d269c3ba359a6f71dcac2f218603e3b.webp)

Explicit mappings express which columns the automation is intended to change.

On the unique branch, configure the n8n Google Sheets node using the steps below. Update Row updates existing rows, and manual mapping specifies individual columns. Edit Fields can discard fields that were not explicitly set.

1. Add Edit Fields to the unique branch. Set record_id from requested_id and automation_status from proposed_value.
2. Enable the option that discards other input fields.
3. Add Google Sheets Update Row for the Records sheet and select record_id as the matching column.
4. Choose Map Each Column Manually. Map record_id and automation_status only; do not use Append or Update Row.

Omit team_notes entirely; remove its mapping instead of leaving it blank. Supplied master-branch implementation evidence shows that manual mapping for Google Sheets node versions 4 and later converts mapped null or undefined values to empty strings. Another helper skips null or undefined properties it receives, so upstream mapping matters. The documentation is undated and the implementation is unpinned; installed releases and interface labels may differ.

For the review branch, use Google Sheets Append Row on the Review sheet. Manually map requested_id, proposed_value, classification and match_count from classification output. Append Row adds a row at the end; this review procedure is our suggested design, not a built-in exception-review feature.

## 4. Verify changes and troubleshoot

![Paired ledger strips and four fixture trays support checking updates and preserved team notes.](/blog/en/article-36155b55-8284-4702-bfa6-d3aaec7384b5/26f3736b3d7ebe0b0cce2397d0c21abbf856008c87207890d82322a94ef72125.webp)

Compare before-and-after contents across the suggested acceptance cases.

Record team_notes before each run, execute the workflow, then re-read the sheet. Use these suggested acceptance criteria for your n8n Google Sheets workflow.

**Suggested acceptance criteria, not observed results**

| Request | Records sheet | Review sheet |
| --- | --- | --- |
| Unique ID | Only automation_status changes; team_notes preserved | No entry |
| Missing ID | Unchanged | Missing entry, count 0 |
| Duplicated ID | Both matching rows unchanged | Duplicate entry, matching count |
| Blank ID | Unchanged | Invalid entry, count 0 |

For unexpected results, inspect Executions and use Execute step to inspect individual nodes. Check the selected document, sheet, header and data locations, ID types, classification output and write mappings. If replacing the all-row read with a filtered read, explicitly select Return All Matches: otherwise n8n documents returning only the first matching result.

Column ownership reduces the write surface, but the supplied sources establish no transactional uniqueness, locking or conflict detection between lookup and update. Concurrent edits to automation-owned cells can therefore fall outside this practice workflow's protection.
