## What Changed in n8n 2.40

![A calendar turned to September 15 next to a toolbox holding one new tool among smaller tools, showing a release day.](/blog/en/article-79f36f0f-b51f-440b-9963-60952dd526fd/26e9d42c62cbb51035f7eb4d37c18244f76a62d54dc5f0e1952f01f8f04564ff.png)

A calendar page and a toolbox stand side by side, evoking a release date and a new addition among existing tools.

n8n's official release notes page headlines n8n release notes 2.40, released on September 15, 2026, around two things: a brand-new Microsoft Dataverse core node, and 32 other features bundled into the same release, according to n8n's own release notes page. If your team runs workflows that touch Microsoft's business data platform, or you simply track every core node update that lands in n8n, this release is worth a close look.

The headline item is the Microsoft Dataverse core node itself: a dedicated node for reading and writing rows in a Dataverse environment, shipped as a first-party n8n node rather than a community add-on, per the same release notes.

## The New n8n Microsoft Dataverse Node: Operations and Authentication

![Record cards moving through six stations on a conveyor, representing the Dataverse node's row operations.](/blog/en/article-79f36f0f-b51f-440b-9963-60952dd526fd/82e9aa29c60a30fbd4064783e4c7bffe7672c2571d2df7d6268f8709c401ac85.png)

Record cards pass through six stations on a conveyor, evoking a sequence of operations on data rows.

According to n8n's 2.40 release notes, the new node supports six operations against a Dataverse environment, covering the core actions a workflow would need to manage records there.

- Create a new row
- Update an existing row
- Upsert a row (create or update)
- Delete a row
- Get a single row
- List rows

n8n's GitHub release record for 2.40.0 confirms the node under its 'Features' section, tied to a single pull request, though the commit log itself gives no further detail on credential setup beyond what the docs release notes describe. Readers tracking every n8n core node update will need to rely on n8n's documentation rather than the changelog entry for setup specifics.

Sources: [Release notes | Changelog | n8n Docs](<https://docs.n8n.io/changelog/release-notes>), [Release n8n@2.40.0 · n8n-io/n8n · GitHub](<https://github.com/n8n-io/n8n/releases/tag/n8n%402.40.0>)

## The Other 32 Features at a Glance, With One Concrete Example

Beyond the Dataverse node, n8n describes the release as including 32 other features, a headline count stated directly on the release notes page, though the page does not catalogue all 32 individually in the format reviewed here.

One example n8n's GitHub release log does spell out: the Confluence node was unhidden from the nodes panel and enabled for use as an AI Agent tool, per the 2.40.0 release entry. That single line shows the 32 features are a mixed bag of node visibility changes, AI-agent enablement and other smaller edits, not one uniform type of change.

## What the n8n 2.40 Release Notes Do Not Say

![A clear glass pane beside a foggy glass pane, representing what the release notes state versus leave unstated.](/blog/en/article-79f36f0f-b51f-440b-9963-60952dd526fd/02b9391e8f849de3d6ee070b8a4ccc6515d40c8ad85cb5b0faa3fd78bad84667.png)

A clear pane sits beside a foggy pane, contrasting what is visible with what stays hidden from view.

The 2.40 release notes do not state which n8n editions, Community or Enterprise, the Dataverse node or the other 32 features apply to, nor whether they differ between n8n Cloud and self-hosted instances. That is simply not addressed on the page, not a gap we are filling in on the announcement's behalf.

**What the 2.40 release notes state versus leave unstated**

| Topic | What the release notes say |
| --- | --- |
| Release date | Stated: September 15, 2026 |
| Dataverse node operations | Stated: Create, Update, Upsert, Delete, Get, List Rows |
| Edition (Community vs. Enterprise) | Not documented |
| Hosted plan (Cloud vs. self-hosted) | Not documented |
| Feature-flag status of the Dataverse node specifically | Not documented |

Elsewhere on the same release notes page, n8n notes generally that some features ship behind a feature flag readers may need to enable, and that others roll out gradually to Cloud or self-hosted instances before reaching everyone. The page does not say whether this general caveat applies to the Dataverse node or to any specific one of the 32 other features. We'd treat that silence as a reason for caution before assuming the node is already live everywhere, rather than as a confirmed rollout schedule.

Sources: [Release notes | Changelog | n8n Docs](<https://docs.n8n.io/changelog/release-notes>)

## What Readers Should Do Now

A short checklist for teams deciding how to respond to the release.

The release notes themselves describe what changed, not what a team should do about it. The following is our own editorial guidance for teams deciding how to respond to this n8n release notes 2.40 update; none of it is instruction from n8n itself.

- [ ] Check your own n8n Cloud or self-hosted instance to see if the Dataverse node is visible
- [ ] If the node is present, plan for a Microsoft-side app registration before building workflows that use it
- [ ] Skim the full list of 32 other features for anything touching nodes or credentials your team already relies on, such as Confluence

Our take: given how quickly n8n ships minor versions, a team that only skims a single release risks missing a quieter change, such as a feature-flagged rollout, that later affects their own workflows.

## Background: What Microsoft Dataverse Is

For readers unfamiliar with the term, Microsoft's own product documentation describes Dataverse as a platform for securely storing and managing the data used by business applications, organized into tables of structured records that apps such as Power Apps or Dynamics 365 read and write.

Microsoft's training materials describe Dataverse further as the data foundation behind Power Platform and, increasingly, the engine behind AI agents and Copilot experiences. This background helps explain why a dedicated n8n Microsoft Dataverse node is useful: it gives workflows direct access to records that already sit at the center of many Microsoft-centric business stacks.

Sources: [What is Microsoft Dataverse? - Power Apps | Microsoft Learn](<https://learn.microsoft.com/en-us/power-apps/maker/data-platform/data-platform-intro>), [Describe Microsoft Dataverse - Training | Microsoft Learn](<https://learn.microsoft.com/en-us/training/modules/describe-microsoft-dataverse/>)
