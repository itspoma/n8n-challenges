## What the n8n 3.0 announcement says

The n8n 3.0 announcement, published October 27, 2026, says n8n 3.0.0 beta is available and stable 3.x is expected in early December. n8n describes the release as focused on reliability, stability, and security. The expected window is not a confirmed stable release date. This n8n 3.0 announcement also directs users to instance-specific findings before upgrading.

The announcement says 3.0 applies to self-hosted Community, Cloud, and Enterprise/Business editions. It does not give edition-specific rollout timing or describe every plan’s upgrade process. For now, treat the early-December window as provisional and check n8n’s release notes before setting a production upgrade date.

Sources: [Introducing n8n 3.0 – n8n Blog](<https://blog.n8n.io/introducing-n8n-v3/>)

## n8n 3.0 changes and breaking changes to review

![Docker migration and legacy node blocks beside an unaffected Kubernetes workflow for n8n 3.0 changes.](/blog/en/article-952f11d9-457d-4324-a2c6-cae420d74877/dc786fd2b22eb571d1728e1fc6a52b2b1cf8c6cf145436bb6a68e215e3375d13.webp)

A rerouted workflow and set-aside blocks echo the deployment and node changes covered here.

For self-hosted deployments, the announcement says installations using npm or npx n8n must move to Docker for 3.0. Kubernetes and Helm deployments are unaffected. The announcement does not provide the Docker migration procedure, so consult the applicable official migration documentation before planning that move.

The announcement also says 3.0 removes legacy nodes including Function, Function Item, Item Lists, Cron, and Interval. Many have replacements, and some migrate automatically, but the announcement does not list exact migration steps for every node. It directs readers to separate breaking-changes documentation. We think a node appearing on this list is a reason to review the instance’s Migration Report, not proof that every workflow needs edits. Those documented removals are the n8n breaking changes to review against your own instance.

## Who is affected, and what to do before upgrading

![A version tag, Migration Report, backup, staging bench, and production workflow show n8n upgrade preparation.](/blog/en/article-952f11d9-457d-4324-a2c6-cae420d74877/7a37ad0e6a6a4d2d105668b3430adbe7e1090dd8674831b0d27063f02ca75f2c.webp)

A version tag, report sheet, backup box, staging bench, and production workflow illustrate this section’s preparation guidance.

The changes apply across the editions named in the announcement, but each instance’s affected workflows and settings are identified by its Migration Report. The announcement’s summary does not cover every workflow or operational scenario. Its recommended path is to update to the latest 2.x, open the Migration Report, fix or mark “won’t fix” everything it flags, take a full backup, and upgrade a test or staging instance before production. As editorial advice, first check your current version: the Help Center says the report is available from Settings on version 2.39 or later, so update to the latest 2.x if you are below that threshold. The n8n 3.0 announcement gives this instance-specific review a practical starting point.

In the n8n 3.0 announcement, the preparation sequence begins with the latest 2.x release and the Migration Report.

- [ ] Check the current n8n version; the Help Center says the Migration Report is available on version 2.39 or later.
- [ ] Follow the announcement’s path: update to the latest 2.x and open the Migration Report.
- [ ] Fix or mark “won’t fix” the findings it flags.
- [ ] Take a full backup, then upgrade a test or staging instance before production.
- [ ] If self-hosted on npm or npx, plan the required move to Docker before 3.0.
- [ ] If still on 1.x, plan an intermediate move to 2.x.

If you are still on 1.x, n8n says to move to v2 before 3.0; the Help Center says 1.x support ends December 31, 2026. It does not specify the procedure for moving from 1.x to 2.x. n8n also says that after 3.0 becomes stable, 2.x will receive security and critical fixes for 12 months, while new features will be available on 3.x. In our view, the practical choice is to plan around your current version and the report’s findings rather than assume a single upgrade path fits every instance.

## What the n8n 3.0 announcement leaves unstated

An incomplete route map and sealed manual represent details the announcement leaves open.
