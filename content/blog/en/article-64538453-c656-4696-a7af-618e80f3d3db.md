## Your n8n expressions exercise

This editorial exercise uses n8n expressions to prepare an update payload while keeping missing fields, null, empty strings, zero and false distinct. Your task is to predict each output, inspect it in your own environment, and explain any differences. The suggested expressions and expected outputs below have not been executed or validated.

You need your own n8n Cloud or Self-hosted environment. n8n documents parameter-level expressions with computed-value previews on both. Use Edit Fields in JSON Output mode to supply one synthetic record at a time, followed by another Edit Fields node for mapping. No external API or credentials are needed.

Keep this exercise local: prepare output only. Live writes, HTTP serialization and destination-specific rules for omission, clearing and validation are outside its scope. We think separating payload preparation from delivery makes the field policy easier to reason about.

## Predict presence before choosing defaults

![Two trays contrast narrow and broad fallback policies for the exercise's empty and falsy field values.](/blog/en/article-64538453-c656-4696-a7af-618e80f3d3db/7adbfc7d57c631d8652b0fd0283085fa75fe55fd47c04275eb5104978adace42.webp)

The paired trays illustrate how different fallback policies can preserve or replace different kinds of values.

Create these separate inputs: {}, {"value":null}, {"value":""}, {"value":0}, {"value":false}, {"value":"Ada"}, {"value":[]}, and {"value":{}}. Add "unrelated":"drop-me" to each record. First predict whether value exists, then evaluate {{ Object.prototype.hasOwnProperty.call($json, 'value') }}. MDN distinguishes an own property's presence from its value, including null or undefined.

Compare {{ $json.value ?? 'DEFAULT' }} with {{ $ifEmpty($json.value, 'DEFAULT') }}. MDN documents that ?? defaults for null and undefined; n8n documents a broader empty-value policy for $ifEmpty(). This n8n expressions cheat sheet gives editorial predictions for comparison with your output.

## Build an allowlisted update payload

![A hand selects one allowed field object and leaves unrelated input outside the prepared update parcel.](/blog/en/article-64538453-c656-4696-a7af-618e80f3d3db/56e2cbe988c28c2d9827efb016b949b6b5c231dd58b0287229ba103a117aca2d.webp)

The selection sequence illustrates preparing an allowlisted payload while excluding unrelated input.

For this exercise, use a different policy for updates: omit an absent value, retain an explicit null, and preserve every other supplied value and its type. Allow only the value key into the payload. These are editorial requirements, not a real destination's contract. In our view, defaults and update inclusion deserve separate decisions because they answer different questions.

Suggested payload expression: {{ { ...(Object.prototype.hasOwnProperty.call($json, 'value') ? { value: $json.value } : {}) } }}. MDN documents that spreading an empty object omits the property, while assigning undefined leaves a property present. That distinction concerns JavaScript objects.

Follow this suggested sequence in the mapping node. n8n documents expressions in Edit Fields JSON Output and controls for excluding unmapped input; control labels may differ across installations.

1. Select JSON Output mode and enter the suggested payload expression.
2. Configure output inclusion to exclude the original input fields.
3. Inspect the computed preview, then execute the local mapping node.
4. Compare key presence, value and type against your written prediction for each record.

## Troubleshoot defaults and conditional expressions

If zero or false becomes DEFAULT, check whether you used ||. MDN documents that || falls back for any falsy value, whereas ?? preserves values other than null and undefined. If empty arrays or objects become DEFAULT, compare that result with n8n's documented $ifEmpty() policy.

For n8n expressions, if a condition controls whether a key exists, inspect the resulting object's keys as well as its displayed value. Presence checks and conditional object construction address that requirement; a truthiness check alone cannot distinguish all the supplied cases.

For an optional nested-access extension, Suyash Raj's vendor tutorial illustrates the pattern {{ $json.address?.city ?? 'Unknown' }}. Treat it as a suggested extension. If logic fails after moving into a Code node, n8n documents that top-level transformation helpers such as $if() are available only in the expressions editor.

## Completion criteria and reflection

Finish by recording predicted and observed outputs separately. Use this editorial checklist to decide whether your proposed mapping meets the exercise requirements.

- [ ] The absent-value case produces an empty object.
- [ ] Every present value retains its original value and type.
- [ ] The unrelated field is excluded in every case.
- [ ] Differences between predictions and node output are recorded and investigated.
- [ ] The explanation distinguishes defaulting from property omission.

Suggested reflection: why would replacing an absent field with DEFAULT be different from omitting it? Explain which expression chooses a fallback value and which decides whether to include a property. Before adapting the result to a real integration, replace the exercise policy with that destination's documented contract.
