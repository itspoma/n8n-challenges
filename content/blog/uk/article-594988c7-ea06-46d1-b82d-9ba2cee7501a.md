## Визначте завдання з витягування тексту з PDF у n8n

Ця редакційна вправа пропонує спроєктувати й продемонструвати витягування тексту з PDF у власному середовищі n8n: спрямувати текстовий PDF до Extract From File, сканований PDF — до Mistral AI, а непридатні результати затримати перед подальшим використанням. Запропоновану вправу тут не виконували й не перевіряли.

Для початку потрібні доступ до відповідних вузлів, наявне джерело бінарних файлів і налаштовані облікові дані Mistral. У документації n8n щодо облікових даних зазначено, що для активації ключів API Mistral потрібні платіжні дані й активовані платежі. Вправа починається після отримання файлів; створення інтерфейсу завантаження й автоматичне визначення типів PDF виходять за її межі.

На нашу думку, найкорисніша навчальна мета — розуміти, коли слід затримати результат обробки документа, а не просто домогтися появи тексту.

## Підготуйте позначені тестові документи й еталонний текст

![Текстовий, сканований і нечитабельний тестові PDF лежать поруч з еталонними аркушами для вправи з витягування тексту.](/blog/uk/article-594988c7-ea06-46d1-b82d-9ba2cee7501a/ea8f98870f91bcc61e76059836257efd2699ffa47d0788353baa6f89f0f967c0.webp)

Три зразки документів — чіткий цифровий аркуш, зернистий скан і пошкоджений файл — представляють запропоновані тестові документи вправи.

Використовуйте синтетичні документи без конфіденційних даних: надані джерела не підтверджують строки зберігання даних провайдером, місце їх зберігання чи договірні гарантії конфіденційності. Вручну позначте маршрут кожного тестового документа й збережіть оригінал для порівняння. Ці запропоновані вхідні дані визначають вправу, а не становлять перевірений набір тестів.

Підготуйте наведені нижче тестові документи. iTechGuides пояснює, що сторінки, які містять лише зображення, потребують OCR, тож для сканованого документа доцільно передбачити окремий маршрут.

**Запропоновані редакційні тестові документи**

| Тестовий документ | Маршрут, призначений вручну | Еталон |
| --- | --- | --- |
| PDF із текстовим шаром | Extract From File | Відомий текст в оригіналі |
| Сканований PDF | Mistral AI | Текст, переписаний вручну |
| Нечитабельний файл | Обраний маршрут витягування | Очікуване блокування результату |

## Побудуйте маршрути витягування тексту й OCR

![Текстовий PDF і сканований PDF проходять окремими маршрутами витягування тексту й OCR.](/blog/uk/article-594988c7-ea06-46d1-b82d-9ba2cee7501a/4ac86d6ddf0565615f6625017810b88936cffd504fd6c98c7f0a02963b6b6938.webp)

Прес для витягування й оптична лінза видають паперові смужки, ілюструючи запропоновані маршрути витягування тексту й OCR.

У цьому робочому процесі витягування тексту з PDF у n8n обирайте маршрут за вручну призначеними позначками тестових документів. iTechGuides описує вибір операції Extract From PDF у вузлі Extract From File; у його рекомендаціях не зазначено версію встановленого n8n. Якщо ви шукали «вузол витягування тексту з PDF у n8n», саме цей вузол і ця операція використані в запропонованій схемі.

Документація Mistral описує OCR для тексту й структурованого вмісту PDF та зображень. Для реалізації, описаної в документації n8n щодо Mistral AI, використовуйте Document → Extract Text з Binary Data та mistral-ocr-latest. Документація не вказує номер версії вузла, а псевдонім моделі може змінюватися. Цей маршрут надсилає документ зовнішньому сервісу.

Щоб зібрати цей інструмент витягування тексту з PDF у n8n, дотримуйтеся запропонованої послідовності. Перегляньте фактичні вихідні дані, перш ніж визначати поле з текстом для перевірки; тут не задано фіксованої відповідності полів відповіді.

1. Перегляньте вхідний елемент і визначте фактичну назву його бінарної властивості.
2. Спрямуйте вручну позначений текстовий документ до Extract From File → Extract From PDF.
3. Спрямуйте сканований документ до Mistral AI, обравши варіант бінарних вхідних даних.
4. У кожному вузлі витягування узгодьте налаштування бінарного поля з властивістю попереднього вузла.
5. Перегляньте кожен результат і визначте текст, який потрібно передати на перевірку якості.

## Розділіть перевірку, схвалення й помилки виконання

![Бар’єр схвалення відділяє прийнятий текст PDF від ізольованих лотків перевірки й помилок виконання.](/blog/uk/article-594988c7-ea06-46d1-b82d-9ba2cee7501a/c6bdd3588ce4e91c16957850578d7badd55e90906f4583df1429c020299edd15.webp)

Бар’єр, яким керує людина, і два ізольовані лотки ілюструють запропоноване розділення схвалення, перевірки вмісту й помилок виконання.

Вузол If у n8n підтримує умовні порівняння. Правила прийняття результату на схемі — це редакційні пропозиції, а не перевірені порогові значення. Джерела не встановлюють точності OCR, порогу впевненості, затримки чи економії.

На нашу думку, текст OCR, який на вигляд читається нормально, потребує такої самої ретельної перевірки, як і явно неповний результат.

Для помилок виконання n8n документує Continue (using error output) і Stop Workflow. Ізоляція помилок залежить від з’єднань у робочому процесі; успішне виконання вузла не підтверджує придатності тексту. Запропонована нижче маршрутизація розділяє ці рішення; автоматизовані інтерфейси схвалення, сповіщення для промислової експлуатації, розбір бізнес-полів і підготовка розгортання до надійної роботи залишаються поза межами вправи.

## Продемонструйте виконання й проаналізуйте результат

![Руки порівнюють витягнутий текст PDF з оригіналом перед відкриттям засувки для передачі результату далі.](/blog/uk/article-594988c7-ea06-46d1-b82d-9ba2cee7501a/07943e898d3301c335f4db05dc5bee68e39980e2f344fe9e48a4e2402bf66bfe.webp)

Руки порівнюють оригінальний аркуш і аркуш із витягнутим текстом поруч із закритою засувкою, ілюструючи етап ручного схвалення у вправі.

Завершіть вправу з витягування тексту з PDF у n8n, продемонструвавши наведені нижче запропоновані критерії. Якщо вузол не знаходить файл, перевірте наявність [бінарних даних на вході](<https://n8n-challenges.app/uk/blog/binarni-dani-v-n8n-zavantazhennya-zberezhennya-nadsylannya-ta-perevirka-faylu>) й узгодьте назву властивості. Якщо він виконується, але не повертає корисного тексту, перевірте фактичне вихідне поле, перш ніж вважати це помилкою виконання.

- [ ] Продемонструйте призначений маршрут для кожного тестового документа.
- [ ] Перегляньте вихідні дані як витягування тексту, так і OCR.
- [ ] Покажіть, що непридатний і несхвалений текст не може потрапити до кінцевої точки подальшої обробки.
- [ ] Покажіть, що помилки виконання потрапляють лише до кінцевої точки збоїв або зупиняють виконання.
- [ ] Вручну схваліть текст, який відповідає еталону, перед подальшим використанням.

Питання для роздумів: чому текст OCR може виглядати читабельним, але не відповідати оригіналу? Запропоноване рішення — показати розбіжність з еталоном, затримати результат і пояснити, яке рішення спрямувало його на перевірку.
