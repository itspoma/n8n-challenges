## Підготуйте вправу з вузлом n8n Aggregate

Вузол n8n Aggregate може зібрати оновлення команди в один список для перевірки. У цьому посібнику ви створите набір даних із полем updates, [перевірите неповні записи](<https://n8n-challenges.app/uk/blog/validatsiya-danykh-u-n8n-vprava-pered-zapysom-danykh-kompaniy>) й вирішите, що має відбуватися, коли оновлень немає. Aggregate збирає дані, але не пише текстового підсумку.

Вам потрібен доступ до робочого процесу n8n, який можна редагувати. Наявні робочі облікові дані Gmail потрібні лише для необов’язкового кроку надсилання; налаштування облікових даних і формування тіла листа виходять за межі цієї вправи. У документації n8n не вказано відповідної версії чи тарифного плану, тому перевірте, які елементи керування доступні у вашому робочому просторі.

На нашу думку, найкорисніше почати з визначення прийнятного набору даних, перш ніж додавати електронну пошту. Для цієї вправи ми пропонуємо таке правило прийнятності: кожне оновлення має містити непорожні поля owner, status і update.

## 1. Створіть контрольовані оновлення команди

Використовуйте вигадані записи, щоб точно розуміти, що надходить до Aggregate. n8n підтримує створення тестових наборів даних за допомогою Code або Edit Fields і редагування вихідних даних вузла. Виконайте ці кроки, щоб підготувати демонстраційні вхідні дані.

1. Скористайтеся Add first step, щоб додати Manual Trigger.
2. Через з’єднувач Add node додайте Edit Fields після тригера.
3. Виконайте Edit Fields, щоб отримати вихідні дані, які можна редагувати.
4. Відкрийте OUTPUT → JSON → Edit, замініть вихідні дані наведеним нижче демонстраційним масивом і виберіть Save.

Використайте цей демонстраційний JSON-масив у редакторі вихідних даних: [{"owner":"Mira","status":"on track","update":"Draft ready"},{"owner":"Jon","status":"blocked","update":"Waiting for access"}]. Збереження відредагованих вихідних даних закріплює їх. Імітація даних, редагування вихідних даних і закріплення — це інструменти розробки; закріплені дані недоступні під час виконань у робочому середовищі.

## 2. Зберіть записи й перевірте результат

![Записки, зібрані в контейнері під лупою, зображують збирання та перевірку даних вузлом n8n Aggregate.](/blog/uk/article-7a3c11f2-80c4-4cd9-a16f-48b049856df0/7d109f2534d240080c28e0cc6581e2a3fbdfaa70d9424ee01987113c99e17ecf.webp)

Ілюстрація показує послідовність збирання та перевірки з цього розділу.

Додайте Aggregate після Edit Fields. Налаштуйте вузол n8n Aggregate за наведеними нижче параметрами, а потім виберіть Execute step, щоб перевірити його вихідні дані, перш ніж додавати будь-яку дію з електронною поштою.

**Початкове налаштування Aggregate**

| Параметр | Значення | Призначення |
| --- | --- | --- |
| Режим Aggregate | All Item Data | Зібрати дані елементів в один список |
| Put Output in Field | updates | Назвати зібраний список |
| Include | All fields | Зберегти всі вхідні поля |

Для демонстраційних вхідних даних очікуваний зібраний набір має вигляд {"updates":[{"owner":"Mira","status":"on track","update":"Draft ready"},{"owner":"Jon","status":"blocked","update":"Waiting for access"}]}. Перевірте, що обидва записи містяться в updates і зберігають потрібні поля.

Далі змініть Include на Specified Fields і введіть owner,status,update у Fields To Include. Виконайте крок ще раз і перевірте збережені поля. Це вибір полів; прийнятність їхніх значень перевіряйте окремо.

## 3. Перевірте відсутні поля та значення null

![Три кишеньки для записів: з усіма кольоровими вкладками, з порожнім проміжком і з порожньою вкладкою.](/blog/uk/article-7a3c11f2-80c4-4cd9-a16f-48b049856df0/58619d5f5c8ebf35102e2f8eec6fca84aea930b6924d091ae3b4830e95631648.webp)

Повні вхідні дані, відсутні поля та значення null — окремі тестові випадки для перевірки.

Відредагуйте [закріплені вхідні дані](<https://n8n-challenges.app/uk/blog/zakripleni-dani-v-n8n-vprava-z-vidtvorennya-ta-vypravlennya-pomylky-mapinhu>), вилучивши поле update із запису Jon, збережіть їх і знову виконайте Aggregate. Потім повторіть перевірку з "update":null. Порівняйте кожен результат із запропонованим правилом прийнятності. Документація n8n не визначає всі варіанти представлення відсутніх полів у режимі All Item Data, тому зафіксуйте, що повертає ваш робочий процес.

Для окремого порівняння перейдіть у режим Individual Fields і агрегуйте update. Keep Missing And Null Values додає елементи null для відсутніх вхідних значень або значень null; коли цей параметр вимкнено, null і порожні значення ігноруються. Під час агрегації кількох окремих полів використовуйте Rename Field і різні значення Output Field Name, наприклад owners та updateTexts.

У цій вправі ми б зберігали записи цілком, адже відповідальна особа, статус і повідомлення пов’язані між собою. Окремі масиви потребують додаткової уваги, якщо відсутні елементи можуть порушити відповідність між ними.

## 4. Перевірте обробку відсутності оновлень

![Порожній кошик для збирання стоїть поряд із порожньою карткою-заповнювачем для тесту відсутності оновлень.](/blog/uk/article-7a3c11f2-80c4-4cd9-a16f-48b049856df0/cbe67bc8ba13e4d42bf7139f3d80539518d7689706488113d8cf1906424842ec.webp)

Порожня колекція та елемент-заповнювач потребують різного тлумачення.

Перш ніж перевіряти відсутність оновлень, поверніть вузол n8n Aggregate у режим All Item Data. Для цього тесту замініть звичайний закріплений набір даних запропонованою нижче тестовою конфігурацією порожнього набору. Документація n8n не визначає стандартного результату Aggregate за відсутності вхідних елементів; перевірте, чи запускається вузол і які вихідні дані доступні.

1. Виберіть Unpin у банері вихідних даних Edit Fields, а потім від’єднайте Edit Fields від Aggregate.
2. Додайте вузол Code і з’єднайте Manual Trigger → Code → Aggregate замість звичайного шляху набору даних.
3. У Code виберіть JavaScript і Run Once for All Items. Замініть код на return []; і залиште Always Output Data вимкненим.
4. Запустіть робочий процес, залишивши Gmail від’єднаним. Перевірте вихідні дані Code, щоб переконатися, що тестова конфігурація створила нуль елементів.
5. У тому самому виконанні перевірте, чи виконався Aggregate і чи має він вихідні дані. Не вважайте вихідні дані попереднього запуску результатом цього тесту.

Always Output Data повертає порожній елемент, коли вузол не створює даних. Такий заповнювач відрізняється від порожнього списку updates і не має вважатися дійсним оновленням команди. Перевірте його перед агрегацією.

Як редакційне правило для цієї вправи пропонуємо не надсилати листа, якщо прийнятних оновлень немає. Якщо додаєте гілку If, вибирайте порівняння exists, is empty або is not empty відповідно до фактичного типу даних. Кілька умов можна поєднувати через AND або OR.

## 5. Усуньте проблеми перед необов’язковим надсиланням листа

Під час тестування залишайте Gmail від’єднаним або деактивованим. Скористайтеся цим контрольним списком, якщо записи зникають або набір даних неповний.

- [ ] Відсутні поля: порівняйте Fields To Include з назвами вхідних полів.
- [ ] Пропущені записи: перевірте, чи Execute Once не обмежує обробку першим елементом.
- [ ] Неочікувані тестові дані: перевірте, чи відредаговані вихідні дані досі закріплені.
- [ ] Порожні вихідні дані: поверніться до тесту відсутності оновлень у кроці 4.

Після успішної перевірки за бажанням під’єднайте налаштований вузол Gmail із робочими обліковими даними. Виберіть Resource Message та Operation Send, потім введіть одержувача, тему, тип листа й перевірений текст повідомлення. Execute step дає змогу спочатку перевірити попередній вузол, але не забезпечує обов’язкового погодження.
