## Чотири варіанти MCP, два напрямки

Якщо ви шукаєте GitHub-проєкт n8n MCP server, один із варіантів від спільноти — czlonkowski/n8n-mcp. У n8n також є власні MCP-можливості, і вони виконують інші завдання. У цьому порівнянні розглянуто чотири варіанти: MCP Server Trigger, MCP Client Tool, MCP-сервер на рівні інстансу та спільнотний сервер n8n-mcp. Для кожного ми дивимося на налаштування, те, що він відкриває, контроль доступу й підтримку.

Спершу варто перевірити напрямок. Два вбудовані варіанти, MCP Server Trigger і сервер на рівні інстансу, дають зовнішнім ШІ-клієнтам змогу звертатися до n8n. n8n-mcp — окремий сервер, до якого підключаються ШІ-асистенти, і він може керувати воркфлоу через n8n API, якщо ви надасте йому API-ключ. MCP Client Tool працює у зворотному напрямку: він дає агентам n8n змогу використовувати інструменти зовнішнього MCP-сервера. Є також окремий вузол MCP Client, який викликає MCP-інструменти як звичайні кроки воркфлоу, а не передає їх агенту. Це близький варіант, але в цьому порівнянні він детально не розглядається.

Порівняння спирається лише на документацію n8n і README проєкту. Практичного тестування не проводилося, і жодне з джерел не вимірює продуктивність чи результати безпеки.

## MCP Server Trigger і MCP Client Tool

Згідно з документацією n8n, вузол MCP Server Trigger змушує n8n працювати як MCP-сервер. Він надає URL, через який MCP-клієнти отримують доступ до підключених до нього інструментів n8n. Клієнти можуть автентифікуватися через None, Bearer auth або Header auth.

Є одне експлуатаційне застереження для [self-hosted режиму черги (queue mode)](<https://n8n-challenges.app/uk/blog/n8n-queue-mode-redis-koly-vykhodyty-z-rezhymu-odnoho-instansu>). Якщо ви запускаєте кілька реплік вебхуків, спрямовуйте всі запити /mcp* на одну виділену репліку, інакше з'єднання обриватимуться.

MCP Client Tool у n8n дає AI Agent змогу використовувати інструменти зовнішнього сервера. Він підтримує автентифікацію Bearer, загальний заголовок, кілька заголовків і OAuth2. Також можна обрати, які інструменти сервера бачить агент: All, Selected або All Except. Цей фільтр впливає лише на те, що агент бачить усередині n8n. Він не контролює доступ на віддаленому сервері.

Sources: [MCP Server Trigger | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-langchain.mcptrigger>), [MCP Client Tool | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/cluster-nodes/sub-nodes/n8n-nodes-langchain.toolmcp>)

## MCP-сервер на рівні інстансу: одне з'єднання, увімкнення для кожного воркфлоу

![Контраст між одним воркфлоу MCP Server Trigger і воркфлоу з увімкненим MCP на рівні інстансу](/blog/uk/article-164e9451-3add-4658-8abe-cc9a83c78c07/0fdfa98fd8c8bfabcaf42208c72f286c0a5bf3555cb00941aed6f190e230d3d8.png)

Концептуальне порівняння: один воркфлоу проти одного з'єднання на весь інстанс.

Документація n8n порівнює два вбудовані серверні варіанти так. [MCP на рівні інстансу дає одне з'єднання на інстанс](<https://n8n-challenges.app/uk/blog/posibnyk-z-n8n-mcp-server-bezpechno-pidklyuchayemo-ai-kliyent-do-vashykh-workflow>) із централізованою автентифікацією. MCP Server Trigger відкриває інструменти одного воркфлоу. Доступні можливості залежать від вашої версії n8n. Джерела не вказують, які плани Cloud чи редакції містять MCP на рівні інстансу.

Доступ не розмежовується для кожного клієнта. Кожен підключений клієнт бачить усі воркфлоу з увімкненим MCP, хоча власні дозволи кожного користувача все одно обмежують те, що він бачить. За замовчуванням n8n приймає будь-який OAuth callback URL. Власники й адміністратори можуть обмежити його довіреними URL, і документація зазначає, що цей параметр потребує n8n 2.33.0 або новішої версії.

## Контроль доступу в команді

![Предмети на столі для контролю командного доступу до n8n MCP: замок, відкликана ключ-картка, резервний диск і пісочниця](/blog/uk/article-164e9451-3add-4658-8abe-cc9a83c78c07/23fdfb36e16a3961d61d87d7fe0d4b99fa0cd7184f521b69765d0a57f69c3ecf.png)

Ілюстративний редакційний чекліст для контролю доступу до MCP.

Обирайте варіант насамперед за напрямком. Використовуйте MCP Client Tool, коли агентам потрібні зовнішні інструменти. Використовуйте Server Trigger, щоб опублікувати один підібраний набір інструментів. Використовуйте сервер на рівні інстансу, коли багато воркфлоу мають бути доступні з централізовано керованим доступом. Використовуйте n8n-mcp, коли асистенту для програмування потрібні знання про вузли. Чекліст нижче — редакційна порада, а не перевірений стандарт.

- [ ] Встановіть для Server Trigger автентифікацію Bearer або Header auth, ніколи не None
- [ ] Вмикайте MCP на рівні інстансу лише для потрібних воркфлоу
- [ ] Надавайте перевагу OAuth, щоб відкликати доступ кожного клієнта окремо
- [ ] Обмежте OAuth callback URL довіреними адресами
- [ ] Давайте n8n-mcp API-ключ від непродакшн-інстансу
- [ ] Робіть резервні копії, перш ніж дозволяти ШІ редагувати воркфлоу
