## Ваша вправа з пам’яттю агента n8n

У цій редакційній вправі вам пропонується перевірити пам’ять агента n8n між окремими виконаннями, використовуючи двох вигаданих користувачів і Postgres Chat Memory. Мета — пригадування в межах відповідної сесії без розкриття вигаданого факту з іншої сесії. Вправу не було виконано чи перевірено.

Почніть з уже працездатного чат-процесу n8n, що містить AI Agent і налаштовану чат-модель, а також придатних до використання облікових даних Postgres. Документація n8n описує Postgres Chat Memory як сховище історії чату на основі бази даних і посилається на окремі інструкції з автентифікації. Початкове налаштування облікових даних, [створення агента](<https://n8n-challenges.app/uk/blog/posibnyk-z-ai-agent-u-n8n-stvorit-svoho-pershoho-ahenta>) та розгортання у виробничому середовищі виходять за межі цієї вправи.

Посібник n8n 2026 Production AI Playbook рекомендує ідентифікатори сесій на основі користувачів для пригадування взаємодій між виконаннями. На нашу думку, варто попрактикувати розділення сесій, перш ніж додавати складнішу поведінку агента.

## Налаштуйте вузол пам’яті агента n8n і вхідні дані

![Два різні ключі й окремі відділення сховища символізують вхідні дані сесій Postgres Chat Memory.](/blog/uk/article-d5e2ea15-97c2-44e7-b3ee-98faea875a7c/b224126ecdd0f646112049c88faa85540c96e5609ea4df35fedd4749d52337e9.webp)

Різні ключі символізують вигадані сесії, налаштовані для тестового сховища вправи.

Для пам’яті ШІ-агента n8n із PostgreSQL використовуйте Postgres Chat Memory. Документація n8n описує налаштовуваний ключ сесії, таблицю історії, яка створюється за її відсутності, та контекстне вікно, вимірюване кількістю попередніх взаємодій. Додайте або перевірте це підключення пам’яті, виберіть окрему тимчасову тестову таблицю й запишіть налаштування.

Використовуйте наведені нижче редакційні вхідні дані та обмеження. Обробляйте один вхідний елемент за виконання, оскільки, згідно з документацією n8n, вирази в підвузлах пам’яті обчислюються відносно першого вхідного елемента. Протягом усієї вправи не змінюйте таблицю, модель і налаштування контекстного вікна.

**Пропоновані вигадані вхідні дані та незмінні налаштування вправи**

| Елемент | Пропоноване значення | Призначення |
| --- | --- | --- |
| Ключ сесії Аліси | exercise-alice | Ідентифікувати розмову Аліси |
| Ключ сесії Боба | exercise-bob | Ідентифікувати розмову Боба |
| Вигаданий факт Аліси | Талісман мого проєкту — мідна лисиця. | Закласти факт для пригадування Алісою |
| Вигаданий факт Боба | Талісман мого проєкту — фіолетовий журавель. | Закласти факт для пригадування Бобом |
| Тестова таблиця | Окрема тимчасова таблиця | Зберігати дані вправи окремо |
| Контекстне вікно | Запишіть вибране налаштування | Забезпечити однакові умови порівняння |

## Чергуйте сесії між окремими виконаннями

![Мідні та фіолетові конверти, що чергуються, символізують окремі виконання для Аліси й Боба.](/blog/uk/article-d5e2ea15-97c2-44e7-b3ee-98faea875a7c/14e9036468cfee55760a134e404897aef9406d81a7ba3102c376d90b25843a16.webp)

Чергування конвертів показує пропоновану послідовність повернення до кожної сесії в окремих виконаннях.

Скористайтеся цією послідовністю, щоб дослідити пам’ять агента n8n. Ці запити та критерії завершення є редакційними пропозиціями. Записуйте кожен фактично визначений ключ сесії, ідентифікатор виконання, запит і отриману відповідь; не замінюйте несподівану відповідь тією, яку сподівалися побачити.

1. Виконайте запит із вигаданим фактом Аліси та ключем exercise-alice.
2. В окремому виконанні надішліть вигаданий факт Боба з ключем exercise-bob.
3. Поверніться до exercise-alice й запитайте: Який талісман мого проєкту?
4. Поверніться до exercise-bob в іншому виконанні й поставте те саме запитання.
5. Запитайте в сесії Аліси: Який талісман проєкту Боба? Потім запитайте в сесії Боба про талісман Аліси, не надаючи жодної з відповідей.
6. Зафіксуйте правильне пригадування, відсутність контексту та будь-яке розкриття факту з іншої сесії.

n8n попереджає, що кілька вузлів Postgres Chat Memory за замовчуванням спільно використовують один екземпляр пам’яті, і радить призначати різні ідентифікатори сесій для окремих екземплярів. Різні ключі — це механізм налаштування, а не авторизація автентифікованих користувачів чи гарантія захисту від розкриття даних.

## Досліджуйте пригадування та видиму історію окремо

![Рамка для показу та шухляда сховища розрізняють видиму історію чату й пам’ять Agent.](/blog/uk/article-d5e2ea15-97c2-44e7-b3ee-98faea875a7c/d08dcfefa75042d6da9eaf8b5a808397299418c22b8377626898815934332a40.webp)

Рамка та шухляда розділяють два запитання: що показує чат і який контекст отримує Agent.

Якщо відповіді пам’яті агента n8n вас дивують, скористайтеся цими діагностичними перевірками, перш ніж змінювати кілька налаштувань одночасно. На нашу думку, перевірка фактично визначеного ключа сесії — кращий перший крок, ніж переписування запиту.

**Пропоновані перевірки для несподіваних спостережень**

| Спостереження | Що перевірити спочатку | Що записати |
| --- | --- | --- |
| З’являється факт з іншої сесії | Фактично визначені ключі та випадкове повторне використання | Фактичний ключ у кожному виконанні |
| Власний факт відсутній | Узгодженість ключів і контекстне вікно | Налаштування та проміжні взаємодії |
| Використано кілька вхідних елементів | Обчислення виразів відносно першого елемента | Повторіть з одним вхідним елементом |

Видима історія чату потребує окремої перевірки. У наведеному тут незакріпленому знімку коду Chat Trigger з гілки master, де версія вузла за замовчуванням — 1.5, відновлення історії віджета чату відрізняється від надання пам’яті Agent. Підказка в редакторі також вимагає підключення пам’яті до тригера, коли історія відновлюється з пам’яті; цей знімок не встановлює поведінку для кожної випущеної версії.

## Задокументуйте готовність до видалення та завершіть вправу

![Невикористана гумка біля закритої шухляди символізує перевірку області видалення перед зміною пам’яті.](/blog/uk/article-d5e2ea15-97c2-44e7-b3ee-98faea875a7c/47028680a9553ad716a43a54f48e38c357f3692de903abcbf04eda5a8c5c76fc.webp)

Невикористана гумка залишає видалення на етапі перевірки готовності документації, доки його область дії не з’ясована.

Обмежте роботу з видаленням перевіркою готовності документації. n8n документує операції Chat Memory Manager для отримання, вставлення та видалення повідомлень, зокрема останніх N або всіх повідомлень. Наведена тут документація Chat Memory Manager не встановлює повної процедури видалення даних окремої сесії в Postgres, меж авторизації чи методу перевірки. Окремо загальна документація вузла Postgres попереджає, що Delete без умови вибору рядків видаляє всі рядки; це не інструкція для схеми даних пам’яті.

Перш ніж намагатися щось видалити, знайдіть перелічену нижче документацію для відповідної версії. Ми б залишили видалення заблокованим, доки вибір сесії та перевірка не будуть чітко визначені.

- [ ] Знайдіть інструкції з підключення Chat Memory Manager до потрібної пам’яті Postgres.
- [ ] Задокументуйте, як вибрати конкретну сесію та авторизувати доступ до неї.
- [ ] Підтвердьте область дії операції видалення.
- [ ] Задокументуйте, як перевірити видалення й підтвердити, що інша сесія залишилася недоторканою.

Завершіть вправу, зберігши записи для обох користувачів, позначивши кожну цільову поведінку як спостережену або невдалу та записавши невирішені запитання. Поміркуйте, що ви спостерігали, а що залишається недоведеним: ця невелика вправа не встановлює жодних гарантій щодо безпеки у виробничому середовищі, збереження даних після перезапуску, строку їх зберігання, стирання резервних копій чи довговічності сховища.
