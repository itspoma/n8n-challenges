## Передумови й мета

У цьому посібнику з повторних спроб API в n8n ми налаштуємо вузол HTTP Request, щоб отримувати сторінкові відповіді GET, повторювати запити після тимчасових збоїв і записувати дані зі стабільним ідентифікатором. Перед налаштуванням підготуйте URL API, дані автентифікації, правила пагінації, обмеження на розмір сторінки, поля відповіді та ідентифікатор запису. Надана документація не визначає значень, специфічних для вашого API, тож поки використовуйте заповнювачі, доки не перевірите документацію API або приклад відповіді.

Sources: [HTTP Request | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.httprequest>), [Work with nodes | Build | n8n Docs](<https://docs.n8n.io/build/understand-workflows/workflow-components/work-with-nodes>), [Data Table | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.datatable>)

## 1. Перевірте першу відповідь

![Перевірка відповіді HTTP Request дає змогу визначити її поля та правило пагінації.](/blog/uk/article-34bbbd28-2034-49ef-a65d-35b1679060f3/531b94163c854628736a0f5352700d9dbf8c949828dae26e8d0ac29f4e7074ec.webp)

Перша відповідь HTTP Request показує, яке правило пагінації потрібно налаштувати.

Додайте вузол HTTP Request і задайте метод GET. Виконайте один запит без пагінації, а потім перегляньте тіло відповіді, заголовки та код стану. У документації n8n зазначено, що правила пагінації в API відрізняються, тому перед налаштуванням вузла з’ясуйте, чи API повертає URL наступної сторінки, чи очікує параметр, який змінюється в кожному запиті.

1. Задайте URL запиту й автентифікацію відповідно до вимог документації API.
2. Виконайте один запит без пагінації.
3. Зафіксуйте поля відповіді, розмір сторінки та URL наступної сторінки або параметр сторінки.

Sources: [HTTP Request | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.httprequest>)

## 2. Налаштуйте пагінацію та повторні спроби API в n8n

![Налаштування пагінації та повторів у HTTP Request веде від вибору сторінки до обмеженого відновлення після збою.](/blog/uk/article-34bbbd28-2034-49ef-a65d-35b1679060f3/dd0f2518f547795c33cb2201a5baaad1e8589455e6260dd454a3fd8478646be0.webp)

Пагінація, обмежені повтори й умова зупинки формують послідовність налаштування запиту.

У вузлі HTTP Request увімкніть Pagination і виберіть режим, який відповідає API: змінюйте параметр у кожному запиті або використовуйте URL наступної сторінки з відповіді. Скористайтеся виразом і умовою зупинки, описаними в документації API. n8n надає для виразів змінні $pageCount і $response, але вони не вказують, як саме цей API нумерує сторінки або подає посилання на наступну.

Для повторів задайте скінченний ліміт Retry On Fail і час очікування, що відповідає вимогам API. За документацією n8n, Retry On Fail повторно запускає вузол після збою; у настановах n8n для HTTP Request параметри Max Tries і Wait Between Tries описані як засоби керування повторами. У Microsoft Learn відповіді 429 і 5xx названо типовими кандидатами для повторів, більшість відповідей 4xx — малоймовірними для виправлення повторним запитом, а також рекомендовано дотримуватися Retry-After, якщо цей заголовок надано. Це загальні рекомендації для HTTP; дотримуйтеся правил цільового API.

Ми вважаємо, що найбезпечніше явно задавати обмежені параметри пагінації та повторів, а потім коригувати їх відповідно до задокументованої поведінки API, замість того щоб вважати кожну помилку тимчасовою.

## 3. Виконуйте upsert записів за стабільним ідентифікатором

![Операція upsert у Data Table оновлює відповідний запис або створює новий.](/blog/uk/article-34bbbd28-2034-49ef-a65d-35b1679060f3/5fe2b278a62b33b2f433608c2e36966bb9322cfa7df62732686cf77032dbf379.webp)

Зіставлення ідентифікаторів скеровує upsert: оновити наявний запис або створити новий.

Після отримання записів збережіть їх у Data Table за допомогою операції upsert і умов відповідності на основі стабільного ідентифікатора запису з API. За документацією n8n, upsert оновлює відповідний рядок або створює його, якщо збігу немає. Перш ніж покладатися на цей механізм для запобігання дублюванню рядків, перевірте умови відповідності: документація не гарантує унікальність.

- [ ] Виберіть стабільний ідентифікатор із відповіді API.
- [ ] Налаштуйте умови відповідності upsert, щоб використовувався цей ідентифікатор.
- [ ] Перевірте, що наявний запис оновлюється, а новий створюється, коли збігу немає.

Sources: [Data Table | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.datatable>)
