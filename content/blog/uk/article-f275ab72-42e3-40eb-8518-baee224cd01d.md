## Анонс n8n 2.45 і дата випуску

Анонс n8n 2.45 наведено в офіційних примітках до випуску з датою випуску 20 жовтня 2026 року. Він охоплює версії інтеграцій, публікацію агентів, відображення даних запусків ШІ та інструменти командного перегляду. Запис не містить окремої дати публікації анонсу, тому 20 жовтня слід називати датою випуску.

Зміни стосуються користувачів конкретних вузлів та інтерфейсів, описаних нижче. Анонс не визначає доступність для окремих редакцій, охоплення [хмарних тарифів](<https://n8n-challenges.app/uk/blog/taryfy-n8n-dlya-komand-khmara-chy-self-hosted>) чи загальну доступність. На нашу думку, командам варто розглядати кожну функцію окремо, а не припускати, що всі зміни стосуються їхнього середовища.

Sources: [Release notes](<https://docs.n8n.io/changelog/release-notes.md>)

## Зміни інтеграцій у n8n 2.45

![Дві конструкції робочих процесів стоять поруч, поки рука вставляє новий компонент в одну з них.](/blog/uk/article-f275ab72-42e3-40eb-8518-baee224cd01d/81e7a9f57cd1573643ed632e0b977b1c3781d743c42189938400a13e5312c516.webp)

Окремі конструкції ілюструють різницю між наявними робочими процесами та щойно доданими вузлами інтеграцій.

Зміни інтеграцій розрізняють щойно додані вузли та наявні робочі процеси. У таблиці підсумовано поведінку, описану в примітках до випуску n8n 2.45.

**Поведінка інтеграцій, описана в офіційному записі про n8n 2.45**

| Область | Нова поведінка | Наявні робочі процеси |
| --- | --- | --- |
| Monday.com | Нові вузли за замовчуванням використовують V2 із засобами вибору ресурсів | Залишаються на V1 |
| Ресурси Monday.com | V2 підтримує ті самі ресурси, що й V1, і виправляє створення Column із порожнім Column ID | Залишаються на V1 |
| Версія Kafka | Нові вузли та тригери за замовчуванням використовують V2 на основі librdkafka | Зберігають збережені версії |
| Стиснення Kafka | V2 додає підтримку Snappy, LZ4 і Zstd | Зберігають збережені версії |
| Вихідні дані Kafka V2 | Виробники видають один елемент на кожен вхідний запис | Зберігають збережені версії |
| Acks у Kafka V2 | Відповідає всім синхронізованим реплікам | Зберігають збережені версії |

Для користувачів Azure OpenAI Chat Model у n8n 2.45 облікові дані Microsoft Foundry API Key та Entra ID отримують необов’язкове поле Project, коли Endpoint Type має значення Microsoft Foundry. Список розгортань використовує проєкт з облікових даних, якщо поле Project вузла порожнє; заповнене поле Project вузла має пріоритет.

Ми радимо перед впровадженням цих змін перевірити подальшу обробку вихідних даних Kafka та вибір потрібного Foundry Project. Анонс не містить процедури міграції наявних робочих процесів Kafka.

## Публікація агентів і зворотний зв’язок від ШІ

![Механізм агента чекає за воротами, поки закріплюють інструмент робочого процесу.](/blog/uk/article-f275ab72-42e3-40eb-8518-baee224cd01d/8bd3cf35cd97477570aa56ac578fa06eec19581a6572512ea43f3b6b4b9baccb.webp)

Закриті ворота стоять поруч із механізмом агента, поки рука закріплює з’єднання меншого інструмента.

Для команд, які публікують агентів, n8n 2.45 додає підтвердження з поясненням, що подальші зміни потребують повторної публікації. Неопубліковані інструменти робочих процесів відображаються з посиланнями для публікації та блокують публікацію агента. Анонс не містить ширшої процедури [розгортання агентів](<https://n8n-challenges.app/uk/blog/n8n-ai-agents-i-avtomatyzatsiya-robochykh-protsesiv-cheklist-dlya-navchannya>) або відкату.

Для користувачів, які перевіряють запуски ШІ, заголовок журналу ШІ показує модель, що надала відповідь, у поданнях Rendered і JSON, якщо дані запуску містять назву моделі. Ця модель може відрізнятися від моделі, налаштованої у вузлі. В Agent builder розділ Settings оновлює дані про використання місячного бюджету після завершення ходу; якщо оновлення не вдається, він зберігає останнє відоме значення. У списку вибору субагентів також з’являються персоналізовані піктограма та градієнт кожного агента.

Користувачі Text Classifier можуть за бажанням додавати категорію, оцінку впевненості моделі для неї та карту оцінок категорій. У n8n 2.45 цей параметр за замовчуванням вимкнений і в такому стані зберігає наявний формат вихідних даних без підвищення версії вузла. Ці оцінки не підтверджують точність класифікації та не є каліброваними ймовірностями.

На нашу думку, стан публікації варто враховувати під час [командного перегляду змін](<https://n8n-challenges.app/uk/blog/naykrashchi-praktyky-n8n-vorkflou-dlya-komand-vid-praktyky-do-prodakshnu>), а оцінки впевненості слід трактувати обережно, перш ніж вважати їх висновком про якість.

## Сповіщення про міграцію та перегляд робочих процесів

Для адміністраторів, які переглядають правила міграції, анонс n8n 2.45 додає індивідуальні та масові сповіщення власникам електронною поштою. Індивідуальні сповіщення потребують налаштованого SMTP та електронної адреси власника. Масові сповіщення потребують SMTP і дозволу breakingChanges:migrate. Виявлені проблеми, про які надіслано сповіщення, усе одно потрібно усунути; для пропущених рядків під час масового надсилання з’являється попередження з поясненням причини.

Для команд, які переглядають кілька робочих процесів в Inbox, n8n 2.45 показує назву та закріплену версію кожного процесу в розгортаному елементі. Одночасно відкривається лише один елемент і відображаються його відмінності, а вибір зберігається між Activity та Changes. Анонс не містить результатів тестування продуктивності.

Sources: [Release notes](<https://docs.n8n.io/changelog/release-notes.md>)

## Що перевірити перед використанням оновлення

Анонс n8n 2.45 описує зміни поведінки, а не повну процедуру оновлення. Команд розгортання та інструкцій з усунення несправностей тут немає. Наведений нижче контрольний список — наша редакційна порада щодо перевірки оновлення n8n 2.45, а не план дій, виданий n8n.

- [ ] Визначте, які з оголошених вузлів та інтерфейсів використовує ваша команда.
- [ ] Призначте відповідального за координацію командної перевірки.
- [ ] Запишіть запитання, на які потрібні відповіді перед впровадженням.
- [ ] Задокументуйте рішення команди щодо впровадження та його причини.
