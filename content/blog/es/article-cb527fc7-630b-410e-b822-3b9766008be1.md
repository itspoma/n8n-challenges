## Objetivo, requisitos previos y resultado esperado

En este tutorial, crearás un [pequeño flujo de trabajo](<https://n8n-challenges.app/es/blog/como-elegir-un-primer-flujo-de-trabajo-de-n8n-pequeno-y-comprobable>) con tres nodos conectados: Manual Trigger, HTTP Request y Edit Fields. El flujo solicitará la publicación 1 a JSONPlaceholder, recibirá un objeto JSON y copiará su título en la salida del nodo final. El ejercicio es deliberadamente breve para que puedas concentrarte en cómo se desplazan los datos entre los nodos.

Necesitas acceso a un entorno de n8n. El material oficial para principiantes recomienda n8n Cloud para los nuevos usuarios e indica que hay una prueba gratuita disponible, aunque puedes utilizar otro entorno que ya tengas. Las etiquetas de la interfaz pueden variar según la versión, por lo que un control descrito aquí como Execute Workflow o Test workflow podría tener un texto ligeramente diferente en tu instalación.

El resultado final esperado es un elemento generado por Edit Fields que contiene un campo title mapeado desde la respuesta HTTP. No esperes una frase concreta en ese campo: el ejemplo proporcionado por JSONPlaceholder confirma la estructura de la respuesta, pero abrevia el título. Verifica el valor actual que aparece en los datos de tu propia ejecución.

Sources: [S12](https://docs.n8n.io/build-your-first-workflow), [S10](https://jsonplaceholder.typicode.com/guide/), [S11](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.set), [S3](https://docs.n8n.io/build/work-with-data/reference-data/use-the-ui-mapper)

Sigue practicando las solicitudes HTTP, el mapeo de campos y la depuración nodo por nodo con un reto práctico de n8n.

## Paso 1: Crea el flujo de trabajo y añade un Manual Trigger

Desde tu espacio de trabajo de n8n, elige Start from Scratch para crear un flujo de trabajo. Si quieres, asígnale un nombre descriptivo, como Práctica de mapeo del título de una publicación. Un nombre claro resulta útil cuando vuelves más adelante para comparar ejecuciones de prueba, pero no afecta al funcionamiento del flujo.

Añade un Manual Trigger como primer nodo. Este activador está pensado para la ejecución interactiva: al seleccionar Execute Workflow, el flujo se inicia manualmente. Esto lo hace adecuado para un ejercicio de aprendizaje, porque controlas cuándo comienza cada prueba y puedes inspeccionar los datos resultantes antes de modificar el siguiente nodo. Utiliza un solo Manual Trigger en este flujo.

En esta etapa, ejecuta el activador una vez si tu versión lo permite. Es posible que genere pocos datos de interés, y no pasa nada. Su función aquí es proporcionar un punto de partida deliberado para la solicitud que viene a continuación.

Sources: [S6](https://github.com/n8n-io/n8n-docs/blob/main/docs/get-started/build-your-first-workflow.md), [S1](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.manualworkflowtrigger)

## Paso 2: Configura la solicitud de la publicación

Añade un nodo HTTP Request después del Manual Trigger y confirma que ambos nodos estén conectados. En los parámetros de HTTP Request, selecciona GET como método. El nodo incluye tanto un selector de método como un campo URL para el endpoint.

En el campo URL, introduce el host seguro de JSONPlaceholder, jsonplaceholder.typicode.com, seguido de la ruta /posts/1. Es útil mantener separados el método y el destino en tu lista mental de comprobación: GET describe la operación solicitada, mientras que la URL identifica la publicación 1.

Ejecuta el nodo HTTP Request junto con su activador anterior. Dependiendo de tu versión de n8n, puedes ejecutar el nodo, ejecutar el flujo de trabajo o utilizar un control de prueba con un nombre similar. Lo importante es obtener datos de ejecución recientes de la solicitud, no el texto exacto del botón.

Sources: [S2](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.httprequest), [S10](https://jsonplaceholder.typicode.com/guide/)

## Paso 3: Inspecciona los datos JSON actuales

![Un proceso de tres etapas avanza desde la ejecución manual hasta un objeto JSON y la inspección de su campo title.](/blog/es/article-cb527fc7-630b-410e-b822-3b9766008be1/611e8d96f5ec45fee3e632113afc402ad72e8ebbca569635803028c992ce1fff.png)

Proceso editorial para generar y comprobar los datos de entrada actuales antes del mapeo.

Abre la salida del nodo HTTP Request antes de añadir el mapeo. JSONPlaceholder documenta la respuesta de la publicación 1 como un objeto que contiene id, title, body y userId. Confirma que el elemento actual de tu propia salida incluye un campo title. Esta inspección forma parte del proceso de creación del flujo de trabajo, no es solo una comprobación final.

Presta atención a la diferencia entre los nombres y los valores de los campos. El nombre del campo debe ser title, mientras que el valor es el texto devuelto durante esta ejecución. Como el ejemplo documentado abrevia ese valor, considera la salida actual del nodo como la fuente de referencia para el ejercicio de mapeo.

Si no ves el objeto esperado, detente aquí en lugar de construir una expresión de memoria. Confirma que se haya ejecutado el Manual Trigger, que el nodo HTTP Request también se haya ejecutado y que estés viendo su salida actual. Resolver ahora un problema anterior en el flujo es más sencillo que diagnosticar después un mapeo vacío.

Sources: [S10](https://jsonplaceholder.typicode.com/guide/), [S7](https://n8n-io-n8n.mintlify.app/quickstart)

## Paso 4: Mapea el título con Edit Fields

Añade un nodo Edit Fields después de HTTP Request. Selecciona el modo Manual Mapping y crea un campo para establecerlo con el nombre title. Utilizar el mismo nombre de salida que la propiedad entrante hace que esta primera transformación sea fácil de seguir.

En el panel INPUT, localiza title en el elemento generado por HTTP Request y arrástralo hasta el control de valor de tu nuevo campo title. La documentación de n8n indica que arrastrar datos de entrada hasta un parámetro genera una expresión que hace referencia a esos datos. Esto es preferible a intentar adivinar la expresión, porque utiliza los datos disponibles actualmente para el nodo.

Inspecciona la expresión generada antes de ejecutar el nodo. Debe hacer referencia al valor title entrante, no a un texto de muestra fijo ni a una propiedad no relacionada, como id o body. Si el panel INPUT está vacío, vuelve a ejecutar el activador y HTTP Request; después, regresa a Edit Fields cuando haya datos actuales disponibles de los nodos anteriores.

Sources: [S11](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.set), [S3](https://docs.n8n.io/build/work-with-data/reference-data/use-the-ui-mapper), [S7](https://n8n-io-n8n.mintlify.app/quickstart)

## Paso 5: Ejecuta y verifica el flujo de trabajo completo

Ejecuta el flujo de trabajo completo desde el Manual Trigger. Sigue la ruta de ejecución de izquierda a derecha: el activador inicia la ejecución, HTTP Request recupera el objeto de la publicación y Edit Fields evalúa su mapeo con respecto al elemento entrante.

Abre la salida final de Edit Fields y confirma que contiene un campo title. Compara su valor con el title mostrado en la salida inmediatamente anterior de HTTP Request. Ambos valores deben corresponderse porque el campo final está mapeado desde esa propiedad entrante.

Esta verificación comprueba el objetivo concreto del tutorial: los datos introducidos mediante una respuesta HTTP han llegado a una salida final con una estructura definida deliberadamente. No valida todos los aspectos posibles de un entorno de producción. El flujo sigue siendo un ejemplo práctico y específico sobre solicitudes, inspección de entradas, expresiones y mapeo de campos.

Sources: [S1](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.manualworkflowtrigger), [S10](https://jsonplaceholder.typicode.com/guide/), [S11](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.set), [S3](https://docs.n8n.io/build/work-with-data/reference-data/use-the-ui-mapper)

## Solución de problemas: Inspecciona cada nodo en orden

![Una lista de comprobación sobre una mesa de trabajo guía la inspección desde el activador hasta la salida HTTP y el mapeo de Edit Fields.](/blog/es/article-cb527fc7-630b-410e-b822-3b9766008be1/351d9e1e857b538030b5f34e973a75498e18b34f27ee66918e206eeb052758dd.png)

Lista de comprobación ilustrada para rastrear datos ausentes o incorrectos en un flujo de trabajo.

Cuando el resultado final falte o sea incorrecto, inspecciona el flujo de trabajo siguiendo el orden de ejecución. Primero, confirma que el Manual Trigger haya iniciado la prueba actual. Después, abre HTTP Request y verifica que haya finalizado correctamente y que su elemento JSON actual contenga title. Por último, abre Edit Fields y examina tanto sus datos de INPUT como la expresión generada.

Si HTTP Request no tiene una salida útil, comprueba el método seleccionado y reconstruye el destino a partir del host de JSONPlaceholder y la ruta /posts/1. Si la respuesta existe pero title no aparece, inspecciona el objeto real en lugar de asumir que la estructura documentada se mostró en esta ejecución concreta.

Si HTTP Request contiene title pero Edit Fields no, verifica la expresión en el Expression Editor y asegúrate de que haga referencia al title entrante. Elimina cualquier valor fijo de marcador de posición y vuelve a arrastrar title desde INPUT si es necesario. Cuando el propio INPUT no esté disponible, vuelve a ejecutar el flujo de trabajo o los nodos anteriores antes de editar el mapeo.

Este método nodo por nodo acota la ubicación de un problema sin presuponer su causa. Las indicaciones oficiales para los datos ausentes también recomiendan realizar pruebas manuales, confirmar que los nodos anteriores se hayan ejecutado y revisar las expresiones. Los nombres de los botones pueden variar en tu versión instalada, pero la secuencia de diagnóstico sigue siendo: activador, datos de la solicitud, entrada del mapeo, expresión y salida final.

## Siguiente reto práctico

Cuando este flujo de trabajo funcione, puedes repetirlo con una variación sugerida: mapear tanto title como userId, cambiar el nombre de un campo de salida o hacer referencia deliberadamente a la propiedad equivocada y después diagnosticar el resultado inspeccionando cada nodo. Estas son sugerencias editoriales para practicar, no evaluaciones validadas.

También puedes aplicar la misma secuencia a otra tarea de aprendizaje: activar un flujo de trabajo, obtener datos estructurados, inspeccionar el elemento actual, transformar los campos seleccionados y verificar la salida final. Cambia un elemento cada vez para poder identificar qué modificación afectó a los datos.
