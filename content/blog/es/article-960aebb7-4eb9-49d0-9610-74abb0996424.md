## Prepara un archivo de muestra sin datos sensibles en Dropbox

Este tutorial pasa datos binarios de n8n por cuatro nodos: descarga con HTTP Request, Edit Fields, subida con HTTP Request y descarga de verificación con HTTP Request. El objetivo es recuperar el documento subido y comparar su contenido con el original. Necesitas un espacio de trabajo de n8n en funcionamiento, una cuenta de Dropbox y un archivo de texto existente sin datos sensibles; estos son los requisitos previos del ejercicio que proponemos.

En la configuración de aplicaciones de Dropbox, crea una aplicación de tipo Scoped access con acceso App folder. Habilita files.content.read y files.content.write, aplica los cambios de permisos y genera un token de prueba de corta duración. Dropbox recomienda OAuth para aplicaciones en producción; su implementación queda fuera de este tutorial.

Nuestro ejemplo supone que la aplicación ya puede acceder al archivo de muestra en /sample.txt. Reserva /sample-copy.txt como destino independiente. Esta guía se basa en documentación y no es un informe de pruebas realizadas de primera mano. La documentación oficial de n8n utilizada para estas instrucciones no especifica una versión ni un plan de n8n.

## 1. Descarga los datos binarios de n8n en document

Añade un nodo HTTP Request. Para ambas operaciones de Dropbox de este tutorial, usa HTTPS con el host content.dropboxapi.com y la ruta del endpoint indicada a continuación. Configura la descarga en este orden.

1. Establece Method en POST y la ruta del endpoint en /2/files/download.
2. Añade una cabecera Authorization cuyo valor sea Bearer seguido de un espacio y tu token de prueba.
3. Añade la cabecera Dropbox-API-Arg con el valor {"path":"/sample.txt"}.
4. Establece Response Format en File y Put Output in Field en document.
5. Ejecuta el nodo e inspecciona su salida binaria antes de continuar.

El resultado esperado es un archivo en la propiedad binaria document. Esta propiedad es independiente de los campos JSON y del nombre de archivo sample.txt. El modo de respuesta File por sí solo no demuestra que la respuesta contenga el documento que buscas.

## 2. Conserva los datos binarios de n8n del nodo anterior

![Una mano cambia un papelito azul entre dos bandejas mientras un documento doblado dentro de una funda rosa pasa de una a otra.](/blog/es/article-960aebb7-4eb9-49d0-9610-74abb0996424/02ac8e203c205b700a0ac21a30948e45541a62e3630254d500793237917e894f.webp)

Los objetos de papel separados ilustran cómo editar los metadatos JSON conservando el archivo binario.

Conecta Edit Fields al nodo de descarga. Usa Manual Mapping para añadir el campo JSON sugerido exerciseLabel con el valor dropbox-round-trip. Habilita Include Binary Data para que el archivo entrante aparezca en la salida; después, ejecuta el nodo y comprueba que document siga presente.

Para utilizar los datos binarios de n8n del nodo anterior, el nodo que los recibe necesita el nombre de la propiedad binaria del nodo que los genera: document. Creemos que merece la pena que el equipo adopte el hábito de comprobar el archivo en este punto, porque así el siguiente paso dispone de un contrato de entrada explícito.

## 3. Sube el archivo y recupéralo del destino

![El archivo de muestra original y el documento recuperado de Dropbox aparecen uno junto al otro para comparar su contenido.](/blog/es/article-960aebb7-4eb9-49d0-9610-74abb0996424/5e23003127f4b5c6d40b0f63437af3970c792527ecb0ae48102638d260f86dd4.webp)

Los patrones idénticos del papel ilustran la comparación sugerida entre el contenido original y el recuperado.

Conecta otro nodo HTTP Request después de Edit Fields. La operación de subida de Dropbox recibe el contenido del archivo sin procesar en el cuerpo de la solicitud. Sigue estos pasos para subir los datos binarios de n8n y recuperar el archivo del destino.

1. En el nodo de subida, establece Method en POST y la ruta del endpoint en /2/files/upload, en el mismo host de Dropbox.
2. Añade la cabecera Authorization con el token Bearer y establece Content-Type en application/octet-stream.
3. Establece Dropbox-API-Arg en {"path":"/sample-copy.txt","mode":"add"}.
4. Habilita Send Body, selecciona n8n Binary File como Body Content Type y establece Input Data Field Name en document.
5. Ejecuta la subida e inspecciona los metadatos del archivo que devuelve.
6. Conecta un nodo HTTP Request de verificación. Repite la configuración de descarga, cambiando Dropbox-API-Arg a {"path":"/sample-copy.txt"}, con Response Format en File y el campo de salida document.
7. Ejecuta la descarga de verificación e inspecciona el contenido real del documento recuperado.

Para comprobar el resultado, sugerimos comparar el texto recuperado con el archivo de muestra original, incluidos la puntuación y los saltos de línea. Inspecciona también los metadatos de la subida para comprobar el destino, pero no consideres una confirmación de subida como prueba de que los contenidos son iguales. A nuestro juicio, el recorrido de ida y vuelta solo está completo cuando se ha comprobado el contenido recuperado.

## 4. Resuelve problemas en el traspaso del archivo

Si el recorrido de ida y vuelta falla, sigue esta secuencia de diagnóstico sugerida para localizar dónde desaparece el archivo por primera vez o en qué difiere la solicitud de la configuración necesaria. La última fila se aplica al adaptar el ejercicio a otro receptor.

**Secuencia de diagnóstico sugerida cuando falla el traspaso de un archivo**

| Punto de comprobación | Qué inspeccionar | Siguiente acción |
| --- | --- | --- |
| 1. Salida de la descarga | ¿Está presente document antes de Edit Fields? | Si falta, revisa la configuración de descarga del paso 1. |
| 2. Salida de Edit Fields | ¿Desaparece document entre la entrada y la salida? | Si es así, revisa el ajuste de conservación del paso 2. |
| 3. Solicitud de subida | Si document está presente, ¿en qué difiere la solicitud? | Compara la propiedad de entrada, el formato del cuerpo y las cabeceras con el paso 3. |
| Otro receptor requiere multipart | Nombre del campo de formulario del receptor | Usa Form-Data con un parámetro n8n Binary File y la propiedad de entrada correspondiente. |

## 5. Define controles antes de usar documentos de la empresa

Antes de sustituir el archivo de muestra por documentos de la empresa, acordad los puntos de la siguiente lista de preparación que proponemos. Son decisiones sugeridas; este tutorial no implementa su aplicación automática ni una [política de retención](<https://n8n-challenges.app/es/blog/retencion-de-datos-de-ejecucion-en-n8n-lista-de-comprobacion-para-operaciones-en-alojamiento-propio>) específica para cada despliegue.

- [ ] Documentad un límite de tamaño de archivo aceptado y los formatos permitidos.
- [ ] Definid qué datos sensibles pueden entrar en el flujo de trabajo.
- [ ] Aprobad las rutas de destino e identificad a los responsables del acceso.
- [ ] Estableced reglas de retención y eliminación para los archivos de origen, las copias y los datos de ejecución.
- [ ] Asignad la responsabilidad de implementar y verificar estos controles.

Para n8n autoalojado, la documentación oficial sobre escalado indica que los datos binarios se almacenan en memoria de forma predeterminada y que los archivos grandes pueden provocar fallos. Recomienda N8N_DEFAULT_BINARY_DATA_MODE=filesystem fuera del modo de cola y database para el modo de cola; el modo filesystem no es compatible con el modo de cola. Estas indicaciones de despliegue no constituyen un límite universal de tamaño de archivo seguro ni un paso de configuración de Cloud.
