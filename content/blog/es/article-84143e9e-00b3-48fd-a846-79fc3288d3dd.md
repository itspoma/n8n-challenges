## Ejercicio editorial: reproduce un error con datos fijados en n8n

Usa datos fijados en n8n para mantener estable la respuesta de una API mientras investigas una referencia de campo incorrecta en un nodo posterior. Tu tarea consiste en preparar una respuesta sin datos sensibles, reproducir el [error de mapeo](<https://n8n-challenges.app/es/blog/depura-tus-workflows-de-n8n-antes-de-culpar-a-la-integracion>), corregirlo y comprobar datos nuevos de una integración de prueba. Este es un ejercicio editorial; no se ha ejecutado ni validado.

Necesitas un flujo de trabajo editable en n8n, credenciales configuradas para una integración con una API de prueba, su respuesta JSON y un nodo de mapeo posterior. Aporta tu propio endpoint, autenticación y contrato de respuesta. No uses credenciales de producción y utiliza destinos que no realicen operaciones destructivas; así se aplican al ejercicio las recomendaciones del Centro de ayuda de n8n sobre pruebas controladas.

Para completar el ejercicio se requieren dos comprobaciones: que el mapeo corregido devuelva el valor declarado en los datos de prueba y que una ejecución sin datos fijados mapee correctamente datos nuevos de la integración de prueba. Según el glosario de n8n, los flujos de producción ignoran los datos fijados y obtienen datos nuevos en cada ejecución, por lo que el resultado obtenido con una muestra fija no basta para determinar cómo se comportarán los datos de entrada en producción.

## Prepara una respuesta sin datos sensibles y fíjala

![Dos recipientes anidados contienen objetos personales distintivos y cuentas de colores pastel que los sustituyen; una abrazadera sujeta el segundo recipiente.](/blog/es/article-84143e9e-00b3-48fd-a846-79fc3288d3dd/af18a2d035cfa604ea31af2c6336e91c9fb0d89c621b76378a429b2069e01e1c.webp)

La muestra de prueba conserva la estructura de respuesta necesaria para el ejercicio y sustituye sus valores.

Parte de la respuesta de tu API de prueba. Como precaución editorial, sustituye los valores sensibles antes de incorporarla a la salida de un flujo compartido, conservando los nombres de campo, la estructura anidada y los tipos de valor necesarios para reproducir el error. Revisa toda la muestra de prueba, incluidos los campos no relacionados. La lección comercial de Ynteractive advierte de que no se deben fijar datos reales de clientes en flujos compartidos; estas precauciones sugeridas no son controles de seguridad verificados.

Usa el siguiente ejemplo creado por el autor para definir la discrepancia. La muestra de prueba y el valor esperado son datos de entrada ilustrativos, no un contrato de API proporcionado. Adapta tu respuesta solo cuando su estructura permita aplicar este ejemplo.

**Ejemplo de muestra de prueba y configuración del mapeo**

| Elemento | Configuración sugerida |
| --- | --- |
| Campo anidado | customer.email contiene practice@example.invalid |
| Tipo de valor | Cadena de texto |
| Referencia incorrecta | email en el nivel superior |
| Valor esperado tras la corrección | practice@example.invalid |

El curso comercial de GenAI Unplugged describe cómo abrir el JSON de salida sin procesar mediante el icono de edición situado junto al control de fijación e indica que guardar la salida editada la fija automáticamente. Sigue ese procedimiento en el nodo de la API: pega tu JSON sin datos sensibles, guárdalo y confirma que la salida está fijada. No se especifica ninguna versión de n8n.

Creemos que una muestra de prueba útil conserva la estructura problemática que puso de manifiesto el error; simplificarla hasta eliminar esa estructura frustra el propósito del ejercicio.

## Reproduce la discrepancia y corrige la referencia

Con los datos fijados en n8n, inspecciona la entrada y la salida del nodo posterior en lugar de confiar en el indicador de ejecución. n8n documenta la inspección de entradas y salidas y la generación de expresiones de mapeo arrastrando campos de entrada a los parámetros de un nodo. Usa esas funciones en la siguiente secuencia sugerida.

1. Confirma que INPUT del nodo posterior contiene el campo anidado customer.email.
2. Configura el campo de salida deseado para que haga referencia a email en el nivel superior, ejecuta el paso de mapeo y registra la discrepancia.
3. Sustituye esa referencia arrastrando customer.email desde INPUT hasta el parámetro del nodo posterior.
4. Ejecuta de nuevo el paso de mapeo y compara su salida real con practice@example.invalid.

La operación de mapeo hace referencia a datos existentes; no transforma la propia respuesta de la API. Registra el resultado incorrecto observado sin dar por hecho un mensaje de error o una salida concretos: el ejercicio no prescribe la configuración del nodo de mapeo.

## Desfija los datos y comprueba datos nuevos de prueba

![Un depósito sellado y una entrada de agua abierta alimentan tuberías separadas que desembocan en vasos receptores, con una abrazadera abierta cerca.](/blog/es/article-84143e9e-00b3-48fd-a846-79fc3288d3dd/039724b16d6ea4c1b5b6b350a9c8d4c0353c722069ba44dec7262aab2d34eece.webp)

La salida de la muestra fija y los datos nuevos de prueba permiten comprobar por separado el mapeo corregido.

La guía comercial de depuración de FlowKit recomienda desfijar los datos después de probar con datos fijados en n8n y volver a ejecutar el flujo con datos nuevos de la API. Aplica esa recomendación a tu integración de prueba con las comprobaciones siguientes. Superar ambas aporta evidencia para esos datos de entrada, pero no demuestra de forma exhaustiva que el flujo esté listo para producción.

- [ ] Desfija los datos del nodo de la API y ejecútalo contra la integración de prueba.
- [ ] Inspecciona los datos de entrada devueltos e identifica el valor real del correo electrónico anidado.
- [ ] Ejecuta el mapeo posterior y verifica que su salida coincida con ese valor nuevo.

Si la salida parece desactualizada, vuelve a ejecutar el nodo afectado. n8n documenta que desfijar los datos marca el nodo como pendiente de actualización y que ejecutarlo elimina ese estado; eliminarlo no demuestra que el mapeo sea correcto. Si falla la entrada nueva, compara su estructura anidada y sus tipos de campo con los de la muestra de prueba antes de cambiar la referencia.

En nuestra opinión, una discrepancia entre la muestra de prueba y la entrada nueva es motivo para revisar la cobertura del ejemplo antes de añadir otra solución provisional al mapeo.
