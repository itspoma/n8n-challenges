## Cuatro opciones MCP, dos direcciones

Si buscas un proyecto de GitHub de servidor MCP para n8n, una opción de la comunidad es czlonkowski/n8n-mcp. n8n también tiene sus propias funciones MCP, y cumplen funciones distintas. Esta comparación cubre cuatro opciones: el MCP Server Trigger, el MCP Client Tool, el servidor MCP a nivel de instancia y el servidor comunitario n8n-mcp. Para cada una analiza la configuración, lo que expone, el control de acceso y el mantenimiento.

Lo primero que hay que comprobar es la dirección. Dos opciones integradas, el MCP Server Trigger y el servidor a nivel de instancia, permiten que clientes de IA externos llamen a n8n. n8n-mcp es un servidor aparte al que se conectan los asistentes de IA, y puede gestionar workflows mediante la API de n8n si le das una clave de API. El MCP Client Tool funciona al revés: permite que los agentes de n8n usen herramientas de un servidor MCP externo. También existe un nodo MCP Client independiente, que llama a herramientas MCP como pasos normales del workflow en lugar de dárselas a un agente. Es una opción cercana, pero esta comparación no la trata en detalle.

La comparación se basa únicamente en la documentación de n8n y en el README del proyecto. No se hicieron pruebas prácticas, y ninguna de las fuentes mide resultados de rendimiento o seguridad.

## MCP Server Trigger y MCP Client Tool

Según la documentación de n8n, [el nodo MCP Server Trigger hace que n8n actúe como servidor MCP](<https://n8n-challenges.app/es/blog/tutorial-de-servidor-mcp-en-n8n-conecta-un-cliente-de-ia-a-tus-workflows-de-forma-segura>). Te da una URL que los clientes MCP usan para acceder a las herramientas de n8n conectadas a él. Los clientes pueden autenticarse con None, Bearer auth o Header auth.

Hay una advertencia operativa para [el modo cola en instalaciones self-hosted](<https://n8n-challenges.app/es/blog/n8n-queue-mode-con-redis-cuando-dejar-el-modo-de-instancia-unica>). Si ejecutas varias réplicas de webhook, envía todas las peticiones /mcp* a una única réplica dedicada; de lo contrario, las conexiones fallarán.

El MCP Client Tool de n8n permite que un AI Agent de n8n use herramientas de un servidor externo. Admite autenticación Bearer, por cabecera genérica, por varias cabeceras y OAuth2. También puedes elegir qué herramientas del servidor ve el agente: All, Selected o All Except. Ese filtro solo afecta a lo que ve el agente dentro de n8n. No controla el acceso en el servidor remoto.

Sources: [MCP Server Trigger | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-langchain.mcptrigger>), [MCP Client Tool | Nodes | n8n Docs](<https://docs.n8n.io/integrations/builtin/cluster-nodes/sub-nodes/n8n-nodes-langchain.toolmcp>)

## Servidor MCP a nivel de instancia: una conexión, activación por workflow

![Contraste entre el único workflow del MCP Server Trigger y los workflows activados del MCP a nivel de instancia](/blog/es/article-164e9451-3add-4658-8abe-cc9a83c78c07/0fdfa98fd8c8bfabcaf42208c72f286c0a5bf3555cb00941aed6f190e230d3d8.png)

Comparación conceptual: un workflow frente a una conexión para toda la instancia.

La documentación de n8n compara así las dos opciones de servidor integradas. El MCP a nivel de instancia ofrece una conexión por instancia con autenticación centralizada. El MCP Server Trigger expone herramientas de un solo workflow. Las funciones disponibles dependen de tu versión de n8n. Las fuentes no indican qué planes de Cloud o ediciones incluyen el MCP a nivel de instancia.

El acceso no se limita por cliente. Todos los clientes conectados ven todos los workflows con MCP activado, aunque los permisos de cada usuario siguen limitando lo que puede ver. Por defecto, n8n acepta cualquier URL de callback de OAuth. Los propietarios y administradores pueden restringirlo a URL de confianza, y la documentación indica que ese ajuste requiere n8n 2.33.0 o posterior.

Sources: [Connect to n8n MCP server | Connect | n8n Docs](<https://docs.n8n.io/connect/connect-to-n8n-mcp-server>)

## El proyecto de GitHub de MCP para n8n: czlonkowski/n8n-mcp

El proyecto de GitHub del servidor MCP de n8n tiene otro propósito. Su README lo describe como [un servidor comunitario](<https://n8n-challenges.app/es/blog/checklist-de-nodos-de-comunidad-de-n8n-evaluar-instalar-probar-y-monitorizar>) que proporciona a los asistentes de IA la documentación, las propiedades y las operaciones de los nodos de n8n. Afirma cubrir 2.791 nodos, pero esa cifra es una afirmación del propio proyecto y no se ha verificado de forma independiente.

Sus herramientas de gestión pueden crear y eliminar workflows. Para usarlas, le das al servidor la URL de tu API de n8n y una clave de API. El README desaconseja firmemente dejar que la IA edite directamente workflows de producción.

El contenido del README revisado para este artículo no muestra cómo se autentica el propio endpoint de n8n-mcp, cuáles son las condiciones del servicio alojado ni con qué frecuencia se mantiene el proyecto. Considera esos puntos desconocidos hasta que revises tú mismo el repositorio de GitHub del servidor MCP de n8n.

| --- | --- | --- | --- | --- | --- |
| MCP Server Trigger | Los clientes llaman a n8n | Añade el nodo a un workflow; los clientes usan su URL | Herramientas de un workflow | None, Bearer o Header auth | Modo cola: enruta las peticiones /mcp* a una réplica |
| MCP Client Tool | n8n llama a un servidor | Añade el nodo a un AI Agent y elige la autenticación | Herramientas externas, filtradas para el agente | Bearer, cabecera, varias cabeceras u OAuth2 | Desconocido |

## Controlar el acceso en equipo

![Objetos de escritorio para controlar el acceso del equipo a MCP en n8n: candado, tarjeta revocada, disco de copia de seguridad y bandeja sandbox](/blog/es/article-164e9451-3add-4658-8abe-cc9a83c78c07/23fdfb36e16a3961d61d87d7fe0d4b99fa0cd7184f521b69765d0a57f69c3ecf.png)

Lista editorial ilustrativa para el control de acceso MCP.

Elige la opción primero por dirección. Usa el MCP Client Tool cuando los agentes necesiten herramientas externas. Usa el Server Trigger para publicar un conjunto de herramientas seleccionado. Usa el servidor a nivel de instancia cuando muchos workflows deban ser accesibles con un acceso gestionado de forma centralizada. Usa n8n-mcp cuando un asistente de programación necesite conocimiento de los nodos. La lista siguiente es una sugerencia editorial, no un estándar validado.

- [ ] Configura la autenticación del Server Trigger con Bearer o Header auth, nunca None
- [ ] Activa el MCP a nivel de instancia solo en los workflows que necesites
- [ ] Prefiere OAuth para poder revocar cada cliente por separado
- [ ] Restringe las URL de callback de OAuth a las de confianza
- [ ] Da a n8n-mcp una clave de API de una instancia que no sea de producción
- [ ] Haz copias de seguridad antes de dejar que la IA edite workflows
