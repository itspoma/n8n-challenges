## Prepara el ejercicio con el nodo Aggregate de n8n

El nodo Aggregate de n8n puede recopilar las novedades del equipo en una sola lista para inspeccionarlas. En este tutorial, crearás un payload con un campo updates, [examinarás registros incompletos](<https://n8n-challenges.app/es/blog/validacion-de-datos-en-n8n-un-ejercicio-antes-de-escribir-registros-de-empresas>) y decidirás qué debe ocurrir cuando no haya novedades. Aggregate recopila datos; no redacta un resumen en prosa.

Necesitas acceso a un workflow de n8n que puedas editar. Solo necesitarás una credencial de Gmail que ya funcione para el paso opcional de envío; la configuración de credenciales y la composición del cuerpo del correo quedan fuera de este ejercicio. La documentación de n8n no indica una versión ni un plan aplicables, así que comprueba los controles disponibles en tu espacio de trabajo.

Consideramos que definir un payload aceptable antes de añadir el correo es el punto de partida más útil. Para este ejercicio, sugerimos como criterio de aceptación que cada novedad contenga valores no vacíos en owner, status y update.

## 1. Crea novedades del equipo controladas

Usa registros ficticios para reconocer exactamente qué llega a Aggregate. n8n permite crear conjuntos de datos de prueba con Code o Edit Fields y editar la salida de los nodos. Sigue estos pasos para preparar los datos de entrada del ejemplo.

1. Usa Add first step para añadir un Manual Trigger.
2. Usa el conector Add node para añadir Edit Fields después del disparador.
3. Ejecuta Edit Fields para obtener una salida que puedas editar.
4. Abre OUTPUT → JSON → Edit, sustituye la salida por el array de ejemplo que aparece a continuación y selecciona Save.

Usa este array JSON de ejemplo en el editor de salida: [{"owner":"Mira","status":"on track","update":"Draft ready"},{"owner":"Jon","status":"blocked","update":"Waiting for access"}]. Al guardar la salida editada, queda fijada. La simulación de datos, la edición de la salida y la fijación son herramientas de desarrollo; los datos fijados no están disponibles en las ejecuciones de producción.

## 2. Recopila los registros e inspecciona el resultado

![Unas notas reunidas en un recipiente bajo una lupa representan la recopilación e inspección con el nodo Aggregate de n8n.](/blog/es/article-7a3c11f2-80c4-4cd9-a16f-48b049856df0/7d109f2534d240080c28e0cc6581e2a3fbdfaa70d9424ee01987113c99e17ecf.webp)

La ilustración muestra la secuencia de recopilación e inspección utilizada en esta sección.

Añade Aggregate después de Edit Fields. Configura el nodo Aggregate de n8n con los ajustes siguientes y selecciona Execute step para inspeccionar su salida antes de añadir cualquier acción de correo.

**Configuración inicial de Aggregate**

| Ajuste | Valor | Propósito |
| --- | --- | --- |
| Aggregate mode | All Item Data | Recopilar los datos de los elementos en una sola lista |
| Put Output in Field | updates | Asignar un nombre a la lista recopilada |
| Include | All fields | Conservar todos los campos de entrada |

Para los datos de entrada del ejemplo, el payload recopilado esperado es {"updates":[{"owner":"Mira","status":"on track","update":"Draft ready"},{"owner":"Jon","status":"blocked","update":"Waiting for access"}]}. Comprueba que ambos registros aparecen dentro de updates y conservan sus campos obligatorios.

A continuación, cambia Include a Specified Fields e introduce owner,status,update en Fields To Include. Ejecuta el paso de nuevo e inspecciona los campos conservados. Esto selecciona los campos; revisa por separado si sus valores cumplen el criterio de aceptación.

## 3. Prueba campos ausentes y nulos

![Tres fundas de registros muestran todas las piezas de colores, un hueco abierto y una pieza en blanco.](/blog/es/article-7a3c11f2-80c4-4cd9-a16f-48b049856df0/58619d5f5c8ebf35102e2f8eec6fca84aea930b6924d091ae3b4830e95631648.webp)

Las entradas completas, ausentes y nulas son casos de prueba distintos que debes inspeccionar.

Edita los datos de entrada fijados para omitir el campo update de Jon, guarda y ejecuta Aggregate de nuevo. Después, repite la prueba con "update":null. Inspecciona cada resultado según el criterio de aceptación sugerido. La documentación de n8n no establece todas las formas de representar los campos ausentes en el modo All Item Data, así que anota lo que produce tu workflow.

Para hacer una comparación independiente, cambia a Individual Fields y agrega update. Keep Missing And Null Values añade entradas null para las entradas ausentes o nulas; si está desactivado, se ignoran los valores nulos o vacíos. Al agregar varios campos individuales, usa Rename Field y valores distintos de Output Field Name, como owners y updateTexts.

En este ejercicio conservaríamos los registros completos porque el responsable, el estado y el mensaje están relacionados. Los arrays separados requieren especial cuidado cuando las entradas ausentes pueden alterar su correspondencia.

## 4. Observa cómo se gestiona la ausencia de novedades

![Una cesta de recopilación vacía junto a una tarjeta de relleno en blanco para la prueba sin novedades.](/blog/es/article-7a3c11f2-80c4-4cd9-a16f-48b049856df0/cbe67bc8ba13e4d42bf7139f3d80539518d7689706488113d8cf1906424842ec.webp)

Una colección vacía y un elemento de relleno requieren interpretaciones distintas.

Vuelve al modo All Item Data en el nodo Aggregate de n8n antes de probar qué ocurre sin novedades. Usa la siguiente configuración de prueba sugerida para sustituir el conjunto normal de datos fijados por un conjunto vacío. La documentación de n8n no establece el resultado nativo de Aggregate cuando recibe cero elementos; observa si se ejecuta y qué salida hay disponible.

1. Selecciona Unpin en el aviso de salida de Edit Fields y después desconecta Edit Fields de Aggregate.
2. Añade un nodo Code y conecta Manual Trigger → Code → Aggregate en lugar de la ruta del conjunto de datos normal.
3. Elige JavaScript y Run Once for All Items en Code. Sustituye su código por return []; y deja Always Output Data desactivado.
4. Ejecuta el workflow con Gmail aún desconectado. Inspecciona la salida de Code para comprobar que la configuración de prueba produjo cero elementos.
5. Inspecciona esa misma ejecución para ver si Aggregate se ejecutó y si tiene salida. No interpretes la salida de una ejecución anterior como el resultado de esta prueba.

Always Output Data devuelve un elemento vacío cuando un nodo no produce datos. Ese elemento de relleno es distinto de una lista updates vacía y no debe contar como una novedad válida del equipo. Inspecciónalo antes de la agregación.

Como criterio editorial para este ejercicio, omite el correo cuando no haya novedades aceptables. Si añades una rama If, elige las comparaciones exists, is empty o is not empty según el tipo de datos real. Puedes combinar varias condiciones con AND u OR.

## 5. Resuelve los problemas antes del correo opcional

Mantén Gmail desconectado o desactivado durante las pruebas. Usa esta lista de comprobación cuando desaparezcan registros o el payload esté incompleto.

- [ ] Campos ausentes: compara Fields To Include con los nombres de los campos de entrada.
- [ ] Registros omitidos: comprueba que Execute Once no esté limitando el procesamiento al primer elemento.
- [ ] Datos de prueba inesperados: inspecciona si la salida editada sigue fijada.
- [ ] Salida vacía: vuelve a la prueba sin novedades del paso 4.

Cuando la inspección sea satisfactoria, puedes conectar un nodo Gmail configurado con una credencial que funcione. Selecciona Resource Message y Operation Send, e introduce el destinatario, el asunto, el tipo de correo y un cuerpo de mensaje revisado. Execute step permite inspeccionar primero un nodo anterior; no impone una aprobación obligatoria.
