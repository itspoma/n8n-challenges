## Delimita la comprobación de autenticación OData de SAP en n8n

Esta lista de comprobación de autenticación OData de SAP en n8n está dirigida a equipos que se conectan a un servicio OData existente de SAP S/4HANA local o Private Cloud con credenciales de cliente OAuth ya acordadas. El objetivo es verificar una lectura limitada y aprobada antes de desarrollar el resto del flujo de trabajo.

Considera las comprobaciones siguientes como orientación editorial, no como normas obligatorias de SAP. Se trata de verificar la conexión, no de aprovisionar el servidor: la activación del servicio, el registro OAuth y la creación de roles siguen siendo requisitos previos a cargo del administrador de SAP. Los acuerdos de comunicación de Public Edition, los flujos de autenticación alternativos, [SAP Business One y la intermediación mediante SAP BTP](<https://n8n-challenges.app/es/blog/integracion-de-n8n-con-sap-que-esta-realmente-soportado-hoy>) quedan fuera de esta lista.

Las piezas que encajan muestran por qué los requisitos del servicio y los ajustes de las credenciales deben coincidir.

La guía de Shusei Sekiya publicada en SAP Community en marzo de 2026 describe los roles de autorización, el registro del cliente OAuth y la configuración de ámbitos para esta familia de despliegues. Son instrucciones de la comunidad: el acceso al servicio, la autorización de ámbitos y los permisos sobre datos de negocio dependen de la API de destino, así que no copies sus roles de ejemplo indiscriminadamente.

Creemos que una entrega precisa de la configuración es más útil que una credencial que simplemente parece completa. Pide al responsable de SAP que confirme los siguientes elementos; la preparación estará completa cuando cada uno tenga un valor acordado o una explicación explícita.

- [ ] Confirma la versión de SAP, el despliegue, la versión de OData, la URL directa del servicio OData y el conjunto de entidades aprobado.
- [ ] Obtén la URL del token y la confirmación del tipo de concesión client credentials.
- [ ] Confirma si la autenticación del cliente debe ir en la cabecera o en el cuerpo.
- [ ] Obtén el ID y el secreto del cliente mediante el proceso de intercambio de secretos aprobado por tu equipo.
- [ ] Registra los requisitos exactos de ámbitos y los permisos necesarios sobre el servicio y los datos de negocio.

## Configura las credenciales correspondientes de HTTP Request en n8n

La documentación de credenciales de HTTP Request de n8n establece que la configuración de OAuth depende del tipo de concesión. Para client credentials, especifica una URL de token de acceso, un ID de cliente, un secreto de cliente, los ámbitos admitidos por el servicio y la autenticación del cliente en la cabecera o en el cuerpo.

Para configurar la autenticación OData de SAP en n8n, sigue estos pasos sugeridos para trasladar los ajustes aprobados a la credencial de HTTP Request. Marca esta etapa como completada cuando todos los campos coincidan con la configuración entregada por SAP.

1. Selecciona la autenticación OAuth2 y el tipo de concesión client credentials.
2. Introduce la URL del token de acceso, el ID de cliente y el secreto de cliente aprobados.
3. Configura los ámbitos admitidos por el servicio exactamente como se haya acordado.
4. Selecciona la ubicación acordada para la autenticación del cliente: cabecera o cuerpo.
5. Selecciona la credencial configurada en el nodo HTTP Request.

Sources: [n8n-docs/docs/integrations/builtin/credentials/httprequest.md at main · n8n-io/n8n-docs · GitHub](<https://github.com/n8n-io/n8n-docs/blob/main/docs/integrations/builtin/credentials/httprequest.md>)

## Verifica una petición GET limitada y aprobada

![Una llave sola junto a otra con registros inspeccionados muestra la obtención del token y una lectura OData.](/blog/es/article-c1acb763-0b94-4fd7-bbf8-518903fc2860/1b21dd523792b55e09121ae0e21ef08ea9bf15e5f82b8766062f770e3f2cff43.webp)

Las dos composiciones distinguen la obtención de un token de la inspección de los datos devueltos.

La guía de Sekiya publicada en SAP Community en marzo de 2026 muestra una petición GET de OData de Business Partner con $top=5 y $format=json, con HTTP 200 y un JSON de Business Partner como respuesta esperada. Es un ejemplo de la comunidad, no una garantía de que todos los servicios admitan esas opciones de consulta ni una prueba de que tu flujo de trabajo se haya probado.

Consideramos que un intercambio de tokens correcto es un punto de control, no la meta. Para verificar la autenticación OData de SAP en n8n, inspecciona la respuesta real de la lectura antes de ampliar el flujo de trabajo.

Utiliza las siguientes comprobaciones de aceptación sugeridas. Completarlas confirma únicamente la lectura inspeccionada; no demuestra que no existan permisos de escritura ni que la autorización de negocio esté completa.

- [ ] Establece GET explícitamente contra el endpoint de entidades aprobado por SAP.
- [ ] Utiliza un límite de resultados pequeño y aprobado, y un formato admitido por ese servicio.
- [ ] Comprueba que el estado de la respuesta coincida con lo acordado para el endpoint.
- [ ] Inspecciona el contenido de la respuesta para comprobar que incluye la entidad esperada y los datos de negocio permitidos.
- [ ] Evita copiar secretos o contenido sensible de las respuestas en el registro de traspaso.

Sources: [Step-by-Step: Calling S/4HANA Private Cloud Standa... - SAP Community](<https://community.sap.com/t5/technology-blog-posts-by-sap/step-by-step-calling-s-4hana-private-cloud-standard-odata-apis-with-oauth-2/ba-p/14346113>)

## Distingue los fallos del token de los fallos de lectura

La guía de Sekiya publicada en SAP Community en marzo de 2026 ofrece los siguientes puntos de partida para el diagnóstico. No son explicaciones exhaustivas: primero identifica si falló la obtención del token o si la petición OData devolvió un error; después, investiga la configuración correspondiente con el responsable de SAP.

**Puntos de partida para el diagnóstico aportados por la comunidad**

| Señal | Primera comprobación |
| --- | --- |
| invalid_scope | Configuración de ámbitos |
| invalid_client | Credenciales del cliente |
| OData HTTP 403 | Permisos necesarios |
| OData HTTP 404 | Ruta del servicio o activación |

Sources: [Step-by-Step: Calling S/4HANA Private Cloud Standa... - SAP Community](<https://community.sap.com/t5/technology-blog-posts-by-sap/step-by-step-calling-s-4hana-private-cloud-standard-odata-apis-with-oauth-2/ba-p/14346113>)
